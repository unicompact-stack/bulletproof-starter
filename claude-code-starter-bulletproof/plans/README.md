# plans/ — технические планы реализации

## Правила

1. **Один план = одна функция.** Не «сделать проект», а «добавить форму оплаты».
2. **Имя файла:** `YYYY-MM-DD-название-функции.md`
3. **План делится на фазы.** У каждой фазы статус `[ ]` или `[x]`.
4. **В конце плана** - итоговый блок: реализован целиком или нет, что осталось.
5. **Любой агент обязан актуализировать план** после каждой сессии: отмечать сделанное, дописывать что изменилось.
6. **План пишется по спеке.** Критерии готовности плана = критерии приёмки из `specs/`.
7. **Закрытый план уезжает в `archive/`**, а не удаляется.

## Зачем это нужно

Новый чат Клода не помнит, что было сделано в предыдущем. **План - помнит.** Когда открываешь новый чат для продолжения задачи, Клод читает план, видит где остановились, что сделано, что нет - и продолжает оттуда.

Без плана большие задачи разваливаются на 3-й день работы.

## Какой шаблон взять

| Размер задачи | Что это | Шаблон |
|---|---|---|
| **S** — баг-фикс, мелкая правка, 1-2 файла | Лёгкий | [`TEMPLATE.md`](./TEMPLATE.md) |
| **M** — новая фича, рефакторинг модуля, 3-10 файлов | Полный | [`.claude/skills/bulletproof/templates/plan.md`](../.claude/skills/bulletproof/templates/plan.md) |
| **L** — смена архитектуры, новый сервис, 10+ файлов | Полный | тот же, что для M |

**Чем отличаются:** лёгкий шаблон — это цель, контекст, фазы, критерии, риски, итог.
Полный добавляет Challenge Log (обоснование решения против альтернатив), таблицу проблем,
TDD-шаги, гейты, анализ влияния и готовый промпт для запуска каждой фазы.

## Как работать с планом

1. **Создай** план в начале задачи: `plans/2026-04-23-payment-form.md`.
2. **Пройди Challenge Loop** (3 вопроса из этапа 3 Bulletproof) — он вшит в полный шаблон.
3. **Покритикуй** через субагентов: промпт `prompts/methodology/plan-critique.md` (для M и L).
4. **Реализуй** по фазам. После каждой фазы - ставь `[x]`.
5. **В конце** закрой блок «Итог», напиши ретро в `retrospectives/`, план — в `archive/`.
