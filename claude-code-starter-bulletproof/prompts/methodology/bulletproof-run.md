# Прогнать задачу через 12 этапов Bulletproof

**Когда брать:** задача размером M или L — новая фича, рефакторинг, сложный баг, смена архитектуры.
Для задач S (1-2 файла) не бери: там развёрнутый конвейер съест больше времени, чем сама задача.
**Что делает:** переводит задачу в управляемый конвейер — исследование → спека → план с критикой →
реализация по фазам → проверки → анализ влияния → ревью → деплой.
**Результат:** артефакты в `research/`, `specs/`, `plans/`, `progress/` + реализованная фича,
которая не ломает то, что работало.

## Зачем это нужно

Типичный сценарий без методологии: Клод пишет код, говорит «готово»,
а через неделю выясняется, что сломан соседний модуль и половина критериев не выполнена.
**75% ИИ-агентов вносят регрессии в работающий код.** Это не проблема модели — это проблема процесса.

Bulletproof — это и есть процесс.

## Скил уже встроен

Bulletproof лежит в `.claude/skills/bulletproof/` и подхватывается Клодом автоматически.
Этот промпт нужен, когда ты хочешь запустить конвейер **явно** и проконтролировать,
что размер задачи определён верно.

## Промпт

```prompt
Задача: [ОПИШИ ЗАДАЧУ ОДНИМ-ДВУМЯ ПРЕДЛОЖЕНИЯМИ]

Работай по методологии Bulletproof (скил в .claude/skills/bulletproof/SKILL.md).

1. Сначала определи размер задачи и скажи мне его:
   - S — баг-фикс / мелкая правка, 1-2 файла
   - M — новая фича / рефакторинг модуля, 3-10 файлов
   - L — смена архитектуры / новый сервис, 10+ файлов
   Если не уверен — предложи свой вариант и объясни почему. Не спрашивай «а какой размер?».

2. Затем иди по этапам твоего размера. Стандартный порядок:
   - Этап 1. Исследование → research/YYYY-MM-DD-<задача>.md
   - Этап 2. Спека → specs/YYYY-MM-DD-<название>.md (пропускается для S)
   - Этап 3. План + Challenge Loop → plans/YYYY-MM-DD-<название>.md
   - Этап 4. Реализация по фазам (каждая фаза — свежий контекст, своя ветка)
   - Этапы 5-7. Самопроверка → верификация → анализ влияния (внутри каждой фазы)
   - Этапы 8-12. Интеграция → ревью → безопасность → правки → архив плана

3. Перед тем как начать писать код, покажи мне Challenge Log:
   2-3 альтернативных подхода и почему выбранный лучше всех.

4. Перед каждым /clear пиши handoff в progress/<задача>-handoff.md.

5. После завершения: заполни «Итог» в плане, перенеси план в plans/archive/,
   напиши ретро в retrospectives/YYYY-MM-DD_HH-MM_<название>.md.

Деплой — только по моей отдельной просьбе. Не пушь в main.
Всегда отвечай на русском.
```

## Частые ошибки при запуске

- **Не пропускай Challenge Loop.** Три вопроса занимают пять минут и экономят часы.
- **Не разрешай «потом доделаем».** Это самообман: раздел «Правило 40%» и хук Stop
  существуют именно чтобы ловить «не входит в задачу» и «сделаю в следующем PR».
- **Не требуй 12 этапов для мелочи.** Для задач S спека и развёрнутый план — чистые накладные расходы.
- **Читай артефакты, не пересказывай их.** Каждый этап стартует из файла предыдущего
  этапа в свежем контексте — в этом смысл, иначе контекст переполнится.
