# Критика плана через 3 параллельных субагента

**Когда брать:** когда Клод написал первый вариант плана в `plans/YYYY-MM-DD-<название>.md`
и ты готов проверить его прежде чем начинать реализацию. Для задач **M и L** — обязательно.
**Что делает:** запускает 3 субагента параллельно - каждый смотрит на план со своей стороны
(техника, бизнес, UX). Возвращает общий отчёт с правками.
**Результат:** улучшенный план с закрытыми дырами, которые ты бы не увидел один.

## Место в методологии

Bulletproof (этап 3) требует пройти **Challenge Loop** — три вопроса, которые Клод задаёт
сам себе: решает ли план задачу, лучшее ли это решение, нет ли «кода ради кода».
Результат фиксируется в **Challenge Log** в шапке плана.

Эта критика — **второй контур**, не заменяет Challenge Loop, а дополняет:

| | Challenge Loop | Критика субагентами |
|---|---|---|
| Кто смотрит | сам Клод | 3 независимых агента |
| Когда | до финализации плана | после черновика плана |
| Что ловит | необоснованный выбор решения | слепые зоны конкретного чата |
| Где фиксируется | Challenge Log в плане | правки в том же плане |

**Порядок:** Challenge Log → критика субагентами → обновление плана → и только потом реализация.

## Почему это работает

Один агент в одном чате не может «посмотреть на свою работу со стороны». Новый чат +
параллельные субагенты - это и есть «взгляд со стороны», который ловит 80% проблем
**до того** как ты начал кодить.

## Рабочий цикл

1. Клод пишет первичный план в `plans/YYYY-MM-DD-<название>.md` по шаблону из
   `.claude/skills/bulletproof/templates/plan.md` (для M/L) или `plans/TEMPLATE.md` (для S)
2. Ты **копируешь ссылку на файл**, открываешь **новый чат**
3. В новом чате запускаешь промпт ниже
4. Возвращаешься к исходному плану и обновляешь с учётом критики
5. **Только после этого** - реализация

## Промпт

```prompt
У меня есть первичный план реализации: [путь к файлу, например plans/2026-09-09-subscription-backend.md].

Контекст проекта: прочитай .business/INDEX.md и связанные файлы.
Если по плану есть спека в specs/ - прочитай и её.

Задача:
1. Прочитай план целиком.
2. Запусти 3 параллельных субагента на глубокое исследование:
   - агент 1 (техника): проверь реализуемость каждой фазы, найди риски и подводные камни.
     Какие гейты (тесты/линтер/билд) реально прогонять после каждой фазы?
   - агент 2 (бизнес): проверь соответствие плана целям из .business/goals/ и болям из
     .business/audience/. Есть ли в плане работа, которая не служит бизнес-задаче?
   - агент 3 (сценарий): сделай ревью пользовательского сценария - где пользователь
     может застрять, что непонятно, какие краевые случаи не покрыты.
3. Отдельно проверь Challenge Log плана: названы ли 2-3 альтернативы и обоснован ли выбор?
   Если альтернативы слабые или выдуманные - скажи прямо.
4. Собери выводы в один отчёт с конкретными правками: что добавить, что убрать,
   что переформулировать. Каждую правку пометь: обязательно / желательно / на твой вкус.
5. Покажи мне отчёт. Я решу какие правки принять, и попрошу тебя обновить файл плана.

Всегда отвечай на русском.
```

## Что делать с отчётом

- **Критика обоснована** → обнови план
- **Критика промах** (агент не понял контекст) → отметь себе, пропусти
- **Критика поднимает новый вопрос** → не фикси сейчас, добавь в «Открытые вопросы» плана
- **Критика вскрыла новую проблему** → добавь строку в таблицу «Проблемы, которые решаем»

## Правило

Не делай все правки разом. Пройдись по отчёту пункт за пунктом. На каждую правку
принимай осознанное решение «да/нет/позже».

**И главное:** механизм полезен ровно настолько, насколько ты готов услышать
неприятное. Если ты принимаешь только те правки, которые подтверждают твоё решение, —
можешь не запускать.
