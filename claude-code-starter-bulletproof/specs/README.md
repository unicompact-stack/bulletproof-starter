# specs/ — что и зачем

Спека — это **контракт**. Здесь фиксируется, ЧТО мы делаем и ЗАЧЕМ. Никакого «как» —
«как» живёт в `plans/`.

## Правила

1. **Имя файла:** `YYYY-MM-DD-название.md`
2. **Одна спека = одна задача.**
3. **Спека пишется до плана.** План без спеки — это решение без критериев успеха.
4. **Критерии приёмки формулируются проверяемо.** «Работает быстро» — не критерий.
   «Ответ эндпоинта < 200 мс на 1000 записей» — критерий.
5. **Спека НЕ переписывается по ходу реализации.** Если задача изменилась —
   это новая спека или явно зафиксированное изменение с датой.

## Зачем это нужно

Без спеки «готово» определяет Клод по ощущениям. Со спекой он на этапе самопроверки
проходит по каждому критерию и отвечает «да/нет». Спорить не о чём.

## Когда спека не нужна

Задачи размера **S** (баг-фикс, 1-2 файла) идут без спеки — критерий приёмки там
обычно укладывается в одну фразу. Всё, что больше, требует спеки.
