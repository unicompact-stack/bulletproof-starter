# Спека: Читальня — библиотека для чтения

**Дата:** 2026-11-05
**Статус:** черновик, нужно согласование
**Этап:** 4 (идёт параллельно курсу, приоритетнее его)

## Что изменилось

Приложение с уроками сделано и **замораживается**. Оно остаётся как есть:
работает, тесты зелёные, развивать его сейчас не нужно.

Признаём ошибку методологии: на этапе 2 код написали раньше, чем набрали
материал. Поэтому теперь порядок правильный — сначала литература и тексты,
потом (и только если захочется) интерфейс.

## Проблема

Нужных книг и статей по теме много, но они разбросаны: часть в интернете,
часть в PDF, часть вообще не найдена. Искать каждый раз заново — долго.
Читать PDF неудобно, нейросеть их плохо переваривает.

Нужна **личная читальня**: место, где уже лежит всё нужное по моей теме,
в удобном для чтения виде, с поиском и фильтрами.

## Цель

Собрать растущую базу текстов по теме «общение, выступление, актёрское
мастерство», переписанных в единый формат, которые можно просто сесть и
читать — без поиска, без PDF, без воды.

Курс и упражнения — **вторичны**. Они могут вырасти из этой базы потом,
а могут и не вырасти.

## Что входит

1. **Реестр источников** `library/sources.md` — уже есть, 55 позиций,
   продолжает расти. Это каталог: что существует, где лежит, какой оценки.
2. **Карточки источников** `library/notes/S-XXX.md` — уже есть. Короткая
   выжимка по одному источнику.
3. **Статьи-синтезы** `library/articles/A-XXX-*.md` — **новое и главное**.
   Это то, что читается. Одна статья — один вопрос, 3–7 источников внутри,
   собственный текст.
4. **Рубрикатор тем** `library/TOPICS.md` — новое. По каким темам вообще
   собираем базу.
5. **Полные тексты в общественном достоянии** `library/texts/` — новое.
   Книги, срок охраны которых истёк: их можно хранить целиком.

## Что не входит

- Доработка приложения с уроками. Оно заморожено.
- Хранение пиратских копий книг, которые под охраной.
- Перевод и пересказ целых книг (см. раздел про авторское право).
- Аудио, видео, конспекты чужих курсов.

## Формат статьи

Markdown с YAML-шапкой. Почему именно так:

- **Для чтения** — рендерится красиво, со схемами и таблицами.
- **Для нейросети** — чистый текст без разметки PDF, модель читает его
  целиком и может переписать или дополнить.
- **Для правок** — git показывает, что именно изменилось в статье, когда
  появился новый источник.
- **Для схем** — Mermaid: диаграмма описывается текстом, правится как
  текст, не требует рисования в редакторе.

Структура статьи фиксированная: вопрос → короткий ответ → что известно →
схема → что делать → противоречия и пробелы → источники → история правок.

## Авторское право: как делаем

Правило простое: **охраняется форма, а не содержание.** Идеи, факты и
методики свободны; конкретный авторский текст — нет.

| Можно | Нельзя |
|---|---|
| Пересказать идею своими словами, в своей структуре | Переписать книгу целиком «своими словами» — это переработка |
| Собрать в одной статье мысли из 5 книг и сравнить их | Сделать «перевод главы» и выдать за статью |
| Короткая цитата в кавычках с указанием автора | Длинные куски текста без кавычек |
| Свои схемы, свои примеры, свои выводы | Копировать иллюстрации из книги |
| Хранить целиком тексты в общественном достоянии | Хранить PDF книг, которые под охраной |

**Почему статья-синтез безопаснее конспекта одной книги:** когда текст
собран из нескольких источников, с собственной структурой и выводами, это
самостоятельное произведение, а не производное. Поэтому базовая единица
читальни — статья по вопросу, а не «пересказ книги N».

Для книг под охраной в реестре остаётся только карточка: выходные данные,
тезисы, что берём. Сам текст не хранится.

## Критерии готовности этапа

- [ ] Рубрикатор тем согласован, у каждой темы понятно, что в неё входит.
- [ ] По каждой теме найдено минимум 5 источников.
- [ ] Написано минимум 10 статей-синтезов.
- [ ] Каждая статья опирается минимум на 3 источника из реестра.
- [ ] В каждой статье есть раздел «Противоречия и пробелы» — он не пустой.
- [ ] Ни в одной статье нет дословных кусков чужого текста без кавычек.
- [ ] Полные тексты лежат только для источников в общественном достоянии.
- [ ] Статью можно прочитать за один подход: 5–15 минут.

## Как статья обновляется

Статья — живой документ, а не финальный текст. Поводы обновить:

1. Найден источник, который **противоречит** написанному → добавляем в
   раздел «Противоречия и пробелы» или переписываем вывод.
2. Найден источник, который **дополняет** → дописываем абзац и ссылку.
3. Стало понятно, что раздел **не работает на практике** → правим «Что
   делать».

Каждая правка пишется в раздел «История правок» одной строкой: дата, что
изменилось, из-за какого источника. Это нужно, чтобы через полгода было
видно, почему вывод именно такой.

## Открытый вопрос: уроки или темы

Сейчас в реестре у каждого источника есть колонка «Уроки» — привязка к
шести урокам курса. Для читальни это узко: источник про Станиславского не
про урок.

**Решение на сейчас:** колонку оставляем, заполняем ближайшим по смыслу
уроком, параллельно ведём `TOPICS.md`. Когда тем станет больше десяти,
меняем колонку «Уроки» на «Темы» — это потребует правки приложения, и
делать её будем одним заходом, а не сейчас.
