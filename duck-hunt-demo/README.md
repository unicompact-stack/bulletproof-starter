# Тир: утка в прицеле

Небольшой локальный прототип проверки идеи «экран + устройство ввода». Сейчас вместо устройства используется обычная мышь:

- движение мыши — прицел;
- клик — выстрел;
- попадание — `+100` очков;
- на каждый раунд даётся три патрона;
- в первой стае две утки, затем количество растёт до шести;
- после попадания утка падает и остаётся видимой на земле;
- пять стай завершают игру;
- лучший результат сохраняется только в браузере (`localStorage`);
- процедурный пейзаж: вода, холмы, деревья, камыши, трава, облака и солнце;
- анимация махания крыльями, частицы попадания и звуки выстрела/попадания/промаха создаются прямо в браузере без аудиофайлов.

## Запуск

Из этой папки можно открыть `index.html` двойным кликом. Надёжнее запустить локальный сервер из корня репозитория:

```bash
python3 -m http.server 8000
```

Затем открыть <http://localhost:8000/duck-hunt-demo/>.

Для управления с Android нужен встроенный Node-сервер, потому что он принимает координаты от телефона. Из папки `duck-hunt-demo` запустите:

```bash
node server.js
```

После этого на компьютере откройте `http://localhost:4173/`, нажмите «Подключить телефон» и отсканируйте QR-код. Компьютер и Android должны быть подключены к одной Wi‑Fi сети. Сервер определяет локальный IP компьютера, а телефон отправляет прицел и выстрел через HTTP. В текущем Arena-preview QR может вести на внутренний адрес среды, поэтому проверять телефон лучше с локального компьютера.

Проект не использует сторонние библиотеки и изображения: графика утки и игровое поле рисуются в Canvas. Ввод вынесен в отдельный `input.js`: сейчас подключён `MouseInput`, а позже Android-контроллер сможет передавать те же нормализованные координаты `x/y` и событие `fire`, не меняя игровую механику.

На основе идей Adi52 и Erick Wendel добавлены типы уток с разными очками, волны и подготовленный единый слой ввода. Телефон пока специально не подключён.
