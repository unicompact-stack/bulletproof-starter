## Что это за проект

FSM PRO — управление выездными работами для малых сервисных команд России (2-15 человек).
Две роли: **мастер** (мобильная часть) и **руководитель/диспетчер** (веб-панель).

Статус: **рабочий прототип, не продакт.** Собирается и работает, но данные живут
в браузере одного устройства — общей базы нет.

## Структура репозитория

```
fsm-pro/
├── app/                    ← исходники (React + Vite). Вся разработка здесь
│   ├── src/
│   │   ├── components/     ← admin/ (диспетчер), mobile/ (мастер), shared/, docs/
│   │   ├── context/        ← AppContext.tsx — ВСЁ состояние приложения
│   │   ├── data/           ← mockData.ts — демо-данные и шаблоны чек-листов
│   │   ├── db.ts           ← IndexedDB (задачи и фото)
│   │   ├── lib/            ← supabase.ts, db.ts — НЕ ПОДКЛЮЧЕНЫ, ключей нет
│   │   ├── types/          ← Task, User, TaskStatus
│   │   └── utils/          ← geo, image (сжатие фото), statusUtils
│   └── public/             ← manifest, sw.js, иконки
├── docs/                   ← архитектура, конкурентный анализ
├── scripts/                ← деплой на GitHub Pages (Python, через API)
├── specs/                  ← WHAT и ЗАЧЕМ (контракт задачи)
├── research/               ← артефакты исследования
├── plans/                  ← HOW: планы + archive/
├── progress/               ← handoff между сессиями
├── retrospectives/         ← итоги сессий
├── PRODUCT-CORE.md         ← ЧТО НЕЛЬЗЯ ПОТЕРЯТЬ (читать первым!)
├── database_schema.sql     ← модель данных для будущего сервера
└── CHANGELOG.md            ← хроника сессий
```

**Корень репозитория содержит только исходники.** Сборка уходит в `dist/` (в `.gitignore`),
публикуется через GitHub Pages. Никаких закоммиченных `assets/`, `index.html` от сборки,
дублей иконок — это уже стоило бага «на сайте всё старое».

## Как браться за задачу

Размер определяй сам и называй вслух:

| Размер | Что | Путь |
|---|---|---|
| **S** | правка в 1-2 файлах | код → самопроверка → верификация → анализ влияния → гейты |
| **M** | новая фича, 3-10 файлов | этапы 1-10 (спека → план → фазы → проверки → ревью) |
| **L** | смена архитектуры, 10+ файлов | этапы 1-12 |

Полное описание — в `.claude/skills/bulletproof/SKILL.md` (если скил установлен).

## Инварианты (ломать нельзя)

1. **Пять статусов, не больше.** `new` → `assigned` → `in_progress` → `under_review` → `completed`.
   Просрочка — флаг `isOverdue`. Возврат на доработку — возврат в `in_progress` + комментарий.
2. **Мастер не печатает текст.** Новые действия для мастера — кнопками, чипсами, не полями ввода.
3. **Важные действия — внизу экрана и крупные.** Особенно на мобильной части.
4. **Дизайн-система** из `PRODUCT-CORE.md`: фон `#F4F7FA`, акцент `#168BEA`, успех `#2CCB70`, проверка `#9546D8`.
5. **Демо-режим работает.** Он есть только у нас — не ломай его правками.

## Гейты (обязательны перед завершением задачи)

```bash
cd app
npx tsc -b              # 0 ошибок
npx vite build          # сборка успешна
npx oxlint              # 0 ошибок (warning допустимы)
npm test                # тесты зелёные   ← появится после фазы 4
```

**Плюс ручная проверка:** приложение работает как раньше — вход по коду, обе роли,
смена статусов, чат, демо-режим. Любой рефакторинг, который ломает поведение, провален
независимо от зелёных гейтов.

## Как запустить

```bash
cd app
npm install
npm run dev          # http://localhost:5173 — мастер
                     # http://localhost:5173/?view=admin — диспетчер
```

Коды входа: `1111` (работник), `9999` (руководитель). Демо-режим — кнопкой на экране входа.

## Безопасность

- Ключи Supabase — только в `.env` (он в `.gitignore`). `VITE_SUPABASE_ANON_KEY` —
  publishable/anon, в клиентский код класть можно. Connection string pooler — **нельзя**.
- Секреты от деплоя (токены GitHub) — не коммитить. Если засветился — отозвать
  на github.com/settings/tokens.
- Коды доступа — в localStorage. Это уровень демо, не продакшн. Не выдавать за готовую авторизацию.
