[`plans/2026-09-09-fsm-pro-foundation.md`](../plans/2026-09-09-fsm-pro-foundation.md).

Ключевое решение: **менять фундамент, не трогая то, что видит пользователь.**
Поэтому первые две фазы вообще не касаются кода приложения.

## Текущая проблема / следующий шаг

**Блокер, требующий решения владельца:** GitHub Pages сейчас отдаёт корень репозитория.
После чистки в корне нет `index.html` — если запушить это на боевой репозиторий, **сайт упадёт**.

Порядок: сначала настроить GitHub Actions (сборка `app/` → публикация `dist/`),
затем применять чистку на боевом репо. В песочнице чистка уже применена и проверена —
там это безопасно, потому что песочница не является источником публикации.

**Следующий шаг после снятия блокера:** фаза 3, вынос работы с данными из `AppContext.tsx`
в модуль `app/src/storage/` с контрактом из 6 методов.

## Принятые решения

1. **Не переписывать с нуля.** Код живой, ценность в продуктовых решениях, а не в компонентах.
2. **Фазы 1-2 без кода.** Сначала порядок в репо и документах, потом рефакторинг —
   иначе агент работает по вранью в CLAUDE.md.
3. **Монетизация не закладывается в архитектуру.** Она не определена; вкладывать
   сейчас — значит выкидывать потом. Но и не блокируем дорогу.
4. **Поведение не меняется.** Критерий К10: если пользователь замечает разницу — итерация провалена.
