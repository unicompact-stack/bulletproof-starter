# Спека: Фундамент FSM PRO v0.2

**Дата:** 2026-09-09
**Автор:** владелец проекта (решение: вариант Б — «выжать и пересобрать»)
**Связь с бизнесом:** монетизация не определена. Архитектура НЕ должна вкладывать тарифную
логику сейчас, но НЕ должна закрывать дорогу к ней потом.

---

## Проблема

FSM PRO выглядит как продукт, но его нельзя развивать:

1. Данные живут в браузере одного устройства — диспетчер и мастер на разных телефонах друг друга не видят.
2. `AppContext.tsx` (1188 строк) знает всё: задачи, юзеры, чат, офлайн-очередь, 9 ключей localStorage. Любая правка рискует сломать несвязанное.
3. В git закоммичены сборки от пяти версий, иконки трижды, два мёртвых прототипа, архив старых компонентов.
4. `FSM_System_Architecture_and_Specification.md` описывает несуществующий стек (NestJS + PostgreSQL + React Native).
5. Тестов ноль при 20+ пользовательских сценариях.

**Следствие:** подключение сервера сейчас — это не «задача на пару дней», а переписывание половины приложения.

---

## Цель

**Подготовить фундамент так, чтобы подключение сервера стало задачей на 1-2 дня, а не переделкой всего проекта.**

Измеримый результат: слой данных скрыт за интерфейсом, UI не знает где лежат данные,
ядро покрыто тестами, репозиторий содержит только исходники, документы описывают реальность.

---

## Область

### Входит

1. **Чистый репозиторий.** Один источник сборки, без дублей ассетов, без закоммиченных `dist/`,
   без мёртвых прототипов в корне. `.gitignore` это гарантирует.
2. **Честные документы.** `CLAUDE.md` = правила работы, а не хроника сессий.
   Архитектурный документ описывает то, что есть. Хроника остаётся только в `CHANGELOG.md`.
3. **Зафиксированное продуктовое ядро.** Отдельный файл со списком решений, которые
   нельзя потерять при переделке: 5 статусов, дизайн-система, «ноль текста», схема БД, демо-режим.
4. **Слой данных за интерфейсом.** Модуль `storage/` с одним контрактом
   (`getTasks` / `saveTasks` / `getUsers` / `saveUsers` / `getChat` / `saveChat`).
   Реализация «локальная» остаётся прежней по поведению, но UI больше не трогает localStorage напрямую.
5. **Тесты на ядро.** Покрыта статусная машина: 5 статусов, просрочка как флаг,
   возврат на доработку, переходы по ролям.

### Не входит (не делаем в этой итерации)

- Сам Supabase: ключей нет, бизнес-модели нет. Делаем **точку подключения**, а не подключение.
- Реальная авторизация (JWT/сессии). Коды остаются, но уходят за интерфейс.
- Переделка UI, новых экранов, новых фич.
- Тарифы, лимиты, биллинг.
- Миграция данных, RLS, реальный деплой.

> Причина таких границ: выбран вариант Б, а не «всё с нуля». Мы меняем фундамент,
> не трогая то, что пользователь видит.

## Критерии приёмки

- [ ] **К1.** `git status` в чистом клоне показывает только исходники: ни одного файла из `dist/`,
      ни одного `assets/index-*.js`, одна копия иконок.
- [ ] **К2.** `npm run build` создаёт сборку в `dist/`, `dist/` в `.gitignore`,
      в корне репозитория нет `index.html` от сборки.
- [ ] **К3.** Поиск по `app/src` не находит ни одного прямого обращения к `localStorage`
      вне модуля `app/src/storage/`.
- [ ] **К4.** `AppContext.tsx` уменьшился минимум на 25% (с 1188 строк) за счёт выноса работы с данными.
- [ ] **К5.** `CLAUDE.md` содержит правила работы и ноль хроники сессий; вся хроника — в `CHANGELOG.md`.
- [ ] **К6.** Архитектурный документ не содержит упоминаний NestJS, PostgreSQL, React Native, BullMQ.
- [ ] **К7.** Существует файл с зафиксированным продуктовым ядром (минимум 6 позиций из раздела
      «Что работает» исследования).
- [ ] **К8.** Тесты на статусную машину: минимум 8 кейсов, все зелёные.
- [ ] **К9.** Гейты проходят: `npx tsc -b` — 0 ошибок, `npm run build` — успешно, `npm run lint` — 0 ошибок, тесты — зелёные.
- [ ] **К10.** Приложение работает как раньше: вход по коду, обе роли, смена статусов, чат, демо-режим.

> К10 — самый важный. Всё остальное — подготовка. Если пользователь замечает разницу
> в работе, итерация провалена независимо от остальных критериев.

## Ограничения

- **Поведение не меняется.** Это рефакторинг, а не новая версия. Ни одного нового экрана.
- **Без внешних сервисов.** Никаких ключей, аккаунтов, платных подписок.
- **Один разработчик + ИИ-агент.** Архитектура должна читаться без объяснений.
- **Монетизация не определена** — не вкладывать ничего, что придётся выкидывать при смене модели.
- **Работаем в песочнице.** Изменения не уходят на GitHub без отдельной команды владельца.
