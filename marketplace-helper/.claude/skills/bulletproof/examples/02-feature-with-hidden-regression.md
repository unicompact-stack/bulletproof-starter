# Пример 2. Новая фича со скрытой регрессией

## Задача

> «Добавь тёмную тему на страницу настроек».

## Без Bulletproof

Агент:
1. Добавил компонент переключателя темы
2. Создал CSS-переменные для тёмной и светлой тем
3. Обновил вёрстку страницы настроек
4. Изменил глобальный `ThemeProvider`, чтобы поддержать переключатель
5. Проверил тёмную тему — выглядит отлично!
6. Залил в прод

**Через два дня:**

- Пользователи жалуются: графики на дашборде не видны в тёмной теме (белые линии на белом фоне)
- Мобильное меню не реагирует на смену темы
- Просадка производительности: `ThemeProvider` теперь ре-рендерит всех детей при каждом переключении

## С Bulletproof

**Этап 1 — Исследование:** агент составляет карту всех потребителей темы: страница настроек,
графики дашборда (используют захардкоженные цвета), навигация (отдельный CSS), страница профиля.
Выясняет, что библиотека графиков использует inline-стили, а не CSS-переменные.

**Этап 3 — Планирование + Challenge Loop:**

- «План покрывает всех потребителей темы?» — Нет, графики и навигация пропущены. План обновлён.
- «Это самое эффективное решение?» — CSS-переменные для большинства компонентов,
  но графики требуют переопределения конфига. Агент изучает документацию библиотеки графиков.

**Этап 4 — Реализация (фаза 1):** переключатель темы + CSS-переменные + конфиг графиков.

**Этап 7 — Анализ влияния:**

- «Что ре-рендерится при смене темы?» — Найдено: `ThemeProvider` оборачивает всё приложение.
  Решение: мемоизировать значение темы, ре-рендерится только страница настроек.
- «А мобильное меню?» — Найдено: использует отдельный файл стилей. Добавлен fallback на CSS-переменные.

**Результат:**

- Тёмная тема работает везде, включая графики ✅
- Просадки производительности нет ✅
- Мобильная навигация темизируется корректно ✅

## Урок

Исследование нашло проблему с библиотекой графиков до того, как был написан хоть один символ кода.
Анализ влияния поймал проблему с ре-рендерами. Без Bulletproof оба этих бага уехали бы в прод.
