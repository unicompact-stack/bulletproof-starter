# Как сшиты два проекта

Этот репозиторий = [claude-code-starter](https://github.com/artemiimillier/claude-code-starter) (v1.0.3, MIT)
+ [bulletproof](https://github.com/artemiimillier/bulletproof) (v5.0, MIT), объединённые в один шаблон.

Оба проекта одного автора (Артемий Миллер), обе лицензии MIT — юридических препятствий для слияния нет.

## Почему их вообще можно объединить

Они решают **разные половинки одной задачи** и почти не пересекаются по файлам:

| | claude-code-starter | bulletproof |
|---|---|---|
| Суть | шаблон проекта + онбординг | скил-методология разработки |
| Отвечает на вопрос | **ЗАЧЕМ** и **ЧТО** строим | **КАК** писать код, чтобы не сломать |
| Артефакты | `.business/`, `plans/`, `retrospectives/`, `prompts/` | исследование, спека, план с критикой, гейты |
| Язык | русский | английский |
| Форма поставки | GitHub-шаблон, клонируется как проект | клонируется в `.claude/skills/` |
| Файлов в поставке | ~90 | 12 |

Пересечение ровно одно — **папка `plans/`** и **хуки в `.claude/settings.json`**.
Оба конфликта разрешены (см. ниже), дублей не осталось.

## Как решены конфликты

### 1. Папка `plans/` — два шаблона плана

Было: в starter — простой `plans/TEMPLATE.md` (цель → фазы → критерии → итог),
в Bulletproof — свой `templates/plan.md` (Challenge Log, таблица проблем, TDD, гейты, анализ влияния).

**Решение:** оставить оба, развести по размеру задачи.

- `plans/TEMPLATE.md` — **лёгкий**, для задач **S** (1-2 файла). Плюс короткая версия Challenge Loop и обязательный блок анализа влияния.
- `.claude/skills/bulletproof/templates/plan.md` — **полный**, для задач **M и L**. В него добавлены разделы из версии starter: «Риски», «Открытые вопросы», «Итог» — без них план терял связь с бизнесом.

Один шаблон на всё было бы хуже: полный шаблон на задаче из одного файла — чистые накладные расходы,
а лёгкий на смене архитектуры — гарантированные регрессии.

### 2. Хуки `.claude/settings.json` — конфликт по `Stop`

Было: starter вешает на `Stop` **звуковое уведомление** (`type: command`),
Bulletproof — **проверку на самообман** (`type: prompt`). Наивное объединение затирает один из двух.

**Решение:** оба хука живут в массиве `Stop` и выполняются оба — это поддерживается форматом Claude Code.
В `templates/claude-settings.json.example` и в AUTOPILOT (шаг 6) добавлено явное предупреждение:
**не перезаписывай массив `Stop`, добавляй в него**. Это самая вероятная поломка при ручном объединении, поэтому она вынесена в три места: example, SKILL.md, AUTOPILOT.

Дополнительно добавлен `PreToolUse` из Bulletproof (блокировка push в main / `rm -rf /` / `DROP TABLE`) —
в starter его не было.

### 3. Критика плана vs Challenge Loop

Было: в starter — промпт `plan-critique.md` (3 параллельных субагента),
в Bulletproof — Challenge Loop (3 вопроса самому себе). Похоже, но не одно и то же.

**Решение:** оставить оба как два контура и явно описать разницу в `plan-critique.md`:

| | Challenge Loop | Критика субагентами |
|---|---|---|
| Кто смотрит | сам Клод | 3 независимых агента |
| Когда | до финализации плана | после черновика |
| Что ловит | необоснованный выбор решения | слепые зоны конкретного чата |
| Где фиксируется | Challenge Log в шапке плана | правки в том же плане |

Порядок: Challenge Loop → критика субагентами → обновление плана → реализация.

### 4. Язык

Bulletproof переведён на русский целиком. Причина: онбординг, промпты, `.business/` и правила
в `CLAUDE.md` — всё на русском; англоязычный скил в середине русскоязычного проекта
означает смешанные артефакты (план на английском, ретро на русском).

Цена — усложнилось обновление из апстрима. Компенсировано разделом «Обновление из апстрима»
в `.claude/skills/bulletproof/README.md`: копировать только изменения логики, не затирая файл.

### 5. Пути к артефактам

Bulletproof использует `thoughts/research/`. В этом шаблоне — `research/`.
Причина: остальные папки плоские и говорящие (`specs/`, `plans/`, `progress/`),
`thoughts/` выбивается и удлиняет путь без смысла.

Остальное совпало: `specs/`, `plans/`, `progress/`, `plans/archive/`.

### 6. Ретроспектива

В Bulletproof её нет, в starter — обязательна после каждой сессии.
Добавлена в **этап 12** SKILL.md: задача не считается закрытой без ретро в `retrospectives/`.
Это единственное содержательное дополнение к самой методологии.

### 7. Связка с `.business/`

Bulletproof ничего не знает про бизнес-контекст. Добавлены три точки сцепки:

- **Этап 1**: перед исследованием читать `.business/INDEX.md` (нужные файлы, не всё сразу).
- **Этап 2**: цель спеки сверять с `.business/goals/` и болями из `.business/audience/`.
- **Агент ревью**: читает `.business/INDEX.md` перед проверкой кода.

Без этого скил может безупречно реализовать не то, что нужно бизнесу.

## Что проверять при обновлении из апстрима

1. **Структура этапов.** Если в новой версии Bulletproof изменился набор или порядок этапов —
   править `SKILL.md`, таблицу размеров в `CLAUDE.md` и `templates/CLAUDE.md.tmpl`, шаг 6 `AUTOPILOT.md`.
2. **Хуки.** Если изменились хуки — синхронизировать `templates/claude-settings.json.example`,
   раздел «Хуки» в `SKILL.md` и шаги 4-6 `AUTOPILOT.md`. Проверить, что массив `Stop` остался из двух элементов.
3. **Шаблоны.** Если изменились `templates/*.md` — перенести в `.claude/skills/bulletproof/templates/`,
   сохранив русский язык и разделы, добавленные из starter (Риски, Открытые вопросы, Итог).
4. **Агент ревью.** Проверить, что в `agents/code-reviewer.md` сохранён блок про `.business/`.
5. **Счётчики.** После добавления/удаления промптов поправить число в `prompts/INDEX.md`
   (на момент сборки — 17), в `README.md` и в шаге 11b `AUTOPILOT.md`.

## Честные ограничения объединения

- **Обновление из апстрима вручную.** Ни submodule, ни апдейтера. Перенос изменений — ручная работа.
- **Перевод расходится с оригиналом.** Через год формулировки в апстриме и здесь могут отличаться
  сильнее, чем хотелось бы.
- **Применение не проверено на живом проекте.** Все механики перенесены без потери логики, но сам
  merged-шаблон не прогонялся через реальный онбординг — это следующий шаг (см. CHANGELOG, Unreleased).
