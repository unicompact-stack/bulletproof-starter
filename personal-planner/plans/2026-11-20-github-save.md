# План: сохранить приложение и примеры в GitHub

**Дата:** 2026-11-20. **Размер:** M. **Статус:** подготовлено и проверено; факт отправки проверяется по текущей ветке GitHub.

## Цель

По просьбе пользователя сохранить в GitHub текущую версию приложения и девять явно разрешённых им примеров. Работа ведётся в текущей ветке репозитория, без создания другой ветки и без публикации сервиса.

## Проверка плана перед изменениями

1. Уточнить адрес и публичность репозитория, состояние текущей ветки и доступ к ней.
2. Публиковать только `personal-planner/`: код, документацию и согласованные примеры; не включать персональные рабочие данные, резервные копии и секреты.
3. Девять примеров сделать отдельным публичным примером с теми же стабильными ID, чтобы они появились после клонирования и не дублировались у текущего пользователя.
4. Сохранить приватный временный канал `local-inbox/` исключённым из Git. Публичный пример — запасной источник, если временный файл отсутствует; неверный временный файл не заменять молча.
5. Не заменять сохранённые локальные задачи или статусы, не переносить предложения в календарь без подтверждения.
6. Проверить работу после отсутствия приватного файла и при его наличии, а также повторную загрузку, отсутствие дублей и ошибки сети.
7. Перед публикацией запустить тесты и просмотреть полный список staged-файлов и проверку секретов.
8. Коммит и push только в текущую ветку `arena/7b42fb38-bulletproof-starter`; другие ветки не создавать, main не менять.
9. Не обещать, что GitHub автоматически является размещённым веб-приложением или что локальные данные браузера синхронизируются через него.
10. В ответе дать точную ссылку на ветку и пояснить, что репозиторий публичный, а личные данные и настройки браузера не выгружались.
