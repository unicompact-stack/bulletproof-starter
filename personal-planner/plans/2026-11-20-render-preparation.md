# Подготовка календаря для Render

## План до изменений

Цель: создать отдельный безопасный статический вариант для предварительного размещения на Render, не трогая существующие сервисы пользователя. Он не включает автоматическую отправку ВК или защищённое облачное хранение: эти части будут отдельной итерацией после проектирования безопасности. Сборка копирует только явно перечисленные публичные файлы и не должна включать личный временный inbox, сессии, токены и файлы разработки. Текущий календарь и браузерные данные не меняются.

Проверки: (1) сборка из корня и из любого cwd, (2) точный белый список, (3) отсутствие local-inbox, личных и секретных файлов, (4) повторная сборка удаляет устаревшие файлы из output и не трогает исходники, (5) фейковые секреты рядом с исходниками не попадают в output, (6) старые функциональные тесты, (7) изолированный Chromium на собранном сайте 390/1440 px, (8) загрузка ресурсов и демо без личного inbox, (9) сохранение и восстановление тестовых данных, (10) отсутствие настоящих вызовов VK/изменений Render. Проверить настройки Blueprint по официальной документации и оговорить: Render не подключён, статический сайт публичен, localStorage из другого адреса автоматически не переносится. Не создавать/оплачивать ресурсы.

## Итог

- Сборка из явно перечисленных публичных файлов, шаблон Blueprint и пошаговая инструкция подготовлены; личный канал и секреты не копируются. YAML синтаксически проверен, в Render не развёрнут.
- Модульные проверки: 29/29 JS (включая 3 сборки), 9/9 VK с имитацией API. 23/23 сценария Chromium на собранном сайте. Дополнительно проверены настоящий 404 локального inbox, публичные примеры и тестовое сохранение на 390/1440 px без моков канала.
- База, авторизация, безопасная передача и планировщик пока не реализованы. Ни настоящий VK, ни Render, ни личные данные не использовались.
