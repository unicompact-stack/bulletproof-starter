# Тестовая публикация календаря на Render

## Что это и что не готово

`blueprint.yaml` — отдельная конфигурация **публичного статического сайта** для проверки текущего интерфейса. Никакой сервис в Render автоматически не создан. Сборка содержит только семь публичных файлов приложения и согласованные демонстрационные примеры. Временный `app/local-inbox/`, личные сессии, заметки из репозитория, тесты, Python-адаптер ВК и ключи в неё не попадают.

**Это не интеграция ВК:** тестовый сайт не принимает токен, не подключает базу, не синхронизирует браузеры и не отправляет напоминания. Не вводите VK-токен в настройки этого статического сайта, браузер или чат. Код адаптера находится отдельно в `../vk-reminders/` и сейчас не запущен. Продолжение требует отдельного сервера и защищённой системы хранения и входа.

Сайт и его исходный код общедоступны по ссылке. Данные, вводимые в календарь, остаются в localStorage конкретного браузера и адреса (не облачная синхронизация, не сквозное шифрование); любой с доступом к браузеру может их прочитать. Используйте для испытаний вымышленные данные, пока не согласован способ безопасной эксплуатации. Не создавайте публичные каталоги с личными файлами, даже если они исключены Git.

## Перед открытием на новом адресе

Новый адрес Render создаёт **другое браузерное хранилище**. Текущие задачи туда автоматически не перейдут. На старом адресе сохраните и проверьте резервную сессию через «Сохранить сессию»; не удаляйте исходные данные. На новом адресе можно загрузить копию после проверки — восстановление **заменит** данные нового адреса. Не публикуйте файл сессии в репозитории или облачном хранилище с публичной ссылкой. Пользователю может понадобиться сохранить полную JSON-сессию вручную, если окно сохранения в его браузере недоступно. История чата не содержится в копии.

## Простейшая ручная настройка на Render

Ниже описан вариант для репозитория, в котором `personal-planner/` лежит в корне, как сейчас. Если перенесён только каталог `personal-planner`, пути в настройках нужно изменить; инструкция не проверялась на реально созданном сервисе.

1. В Render вручную создайте **новый Static Site** из своего репозитория. Не меняйте существующие проекты.
2. Выберите нужную ветку своей копии. В этом сеансе исходный проект находится в ветке `arena/7b42fb38-bulletproof-starter`.
3. Укажите **Root Directory**: `personal-planner`.
4. **Build Command**: `node render/build.cjs`.
5. **Publish Directory**: `render-public` (относительно Root Directory).
6. Проверьте итоговые условия и расходы в интерфейсе Render до подтверждения. Секреты, база, диск и cron для этого теста не нужны. При желании отключите автоматические развёртывания.
7. Откройте созданный Render-адрес и протестируйте на вымышленных данных. Проверьте, что по `/local-inbox/latest.json` возвращается 404, а в интерфейсе показываются публичные демонстрационные предложения. Если Render отвечает перенаправлением вместо 404 или сборка не работает, не используйте её для личных данных и вернитесь к исправлению.

Альтернатива: создать **новый Blueprint** из репозитория, указав в поле Blueprint Path `personal-planner/render/blueprint.yaml`. Blueprint создаёт отдельный публичный static site; проверьте имя сервиса и область действия перед подтверждением, чтобы не применить его к существующему сервису с таким же именем. Автоматические развёртывания в файле отключены. Подробности: https://render.com/docs/infrastructure-as-code и https://render.com/docs/monorepo-support . Фактическое создание Blueprint в этом сеансе не проверялось.

## Проверка сборки разработчиком

```bash
node personal-planner/render/build.cjs
node --test personal-planner/render/build.test.cjs
node --test personal-planner/app/logic.test.js
python3 -m unittest discover -s personal-planner/vk-reminders -p 'test_*.py'
```

Сборка удаляет и пересоздаёт папку `personal-planner/render-public/`: это временная директория, не храните в ней свои файлы. Она исключена из Git, но игнорирование само по себе ничего не защищает и не шифрует. Интеграционный Chromium-тест `preview.test.cjs` требует запущенного статического сервера, `puppeteer-core` и `CHROME_PATH`; создаёт отдельный временный профиль.

## Следующий этап: автоматические напоминания

Нужны новые отдельные компоненты: защищённый вход и серверное API; понятный пользователю перенос и согласованная синхронизация данных; постоянное хранилище и резервирование; расписание, часовой пояс, учёт изменений/отмены и безопасный журнал отправок; явное включение; проверка с реальным VK. Должны быть продуманы отказ сети, повторения и предел задержки, чтобы не было неожиданных или многочисленных сообщений. Настоящий VK-токен хранится только в секретах серверной службы, не в этой статической сборке. Сервер и расписание не реализованы.

У бесплатного Render веб-сервисы засыпают, их локальные файлы теряются при перезапуске, бесплатная база ограничена по времени. Долговременный диск доступен платным службам и недоступен cron-задачам; cron и база могут требовать отдельной платы. Перед выбором конфигурации уточнить актуальные цены, доступность, бюджет и возможность использовать существующий сервис, не затрагивая его данные: https://render.com/docs/free , https://render.com/docs/disks , https://render.com/docs/cronjobs . Сама статическая сборка пока не хранит личных данных на сервере.
