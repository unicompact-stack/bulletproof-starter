# Bulletproof — встроенный скил

12-этапный workflow разработки: исследование → спека → план с критикой → реализация →
проверки → анализ влияния → ревью → деплой.

**Это не отдельный репозиторий.** Скил встроен в шаблон обычными файлами (vendoring),
поэтому работает сразу после клонирования — никаких `git submodule init` и установок.

## Как пользоваться

Клод подхватывает скил сам, когда видит подходящую задачу (новая фича, рефакторинг,
сложный баг, смена архитектуры). Можно запустить и явно:

- попросить: «сделай по Bulletproof» / «прогони через 12 этапов»
- или взять готовый промпт: `prompts/methodology/bulletproof-run.md`

Размер задачи определяется автоматически: **S** (1-2 файла) идёт по сокращённому
конвейеру, **M** (3-10 файлов) по этапам 1-10, **L** (10+ файлов) по всем 12.

## Что внутри

```
bulletproof/
├── SKILL.md                # полное описание 12 этапов
├── README.md               # этот файл
├── templates/
│   ├── research.md         # артефакт этапа 1
│   ├── spec.md             # контракт: ЧТО и ЗАЧЕМ (этап 2)
│   ├── plan.md             # полный план для задач M/L (этап 3)
│   └── handoff.md          # передача контекста между сессиями
├── agents/
│   └── code-reviewer.md    # агент ревью в свежем контексте (этап 9)
└── examples/               # 3 разбора: как бывает без методологии
```

## Где лежат артефакты

| Этап | Куда пишем |
|---|---|
| 1. Исследование | `research/YYYY-MM-DD-<задача>.md` |
| 2. Спека | `specs/YYYY-MM-DD-<название>.md` |
| 3. План | `plans/YYYY-MM-DD-<название>.md` |
| 3. Лёгкий план (S) | `plans/TEMPLATE.md` |
| 4. Handoff между сессиями | `progress/<задача>-handoff.md` |
| 12. Архив плана | `plans/archive/` |
| 12. Ретро | `retrospectives/YYYY-MM-DD_HH-MM_<название>.md` |

## Обновление из апстрима

Ничего автоматического нет и это нормально: скил — это текст, и обновлять его вручную
раз в несколько месяцев дешевле, чем тащить submodule в каждый новый проект.

Порядок обновления:
1. Открой [SKILL.md апстрима](https://github.com/artemiimillier/bulletproof/blob/main/SKILL.md) и `CHANGELOG.md` там же.
2. Перенеси только изменения логики этапов — не затирай этот файл целиком
   (здесь адаптированные пути и русский язык).
3. Проверь `templates/` — если формат изменился, обнови шаблоны.
4. Прогони чек-лист из `INTEGRATION.md` → раздел «Что проверять при обновлении».
