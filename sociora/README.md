# Sociora — рабочая копия проекта (sociora.ru)

Полноценная локальная копия сайта [sociora.ru](https://sociora.ru): маркетинговый
лендинг + **рабочий личный кабинет** с регистрацией, генерацией постов,
соцсетями, расписанием, аналитикой и тарифами. Бэкенд — на стандартной
библиотеке Python (http.server + SQLite), внешних зависимостей нет.

## Быстрый старт

Кабинет живёт на **отдельном сервере** — сайт и кабинет независимы:

```bash
cd sociora
./start.sh                        # запустит оба сервера сразу
# или по отдельности:
python3 server.py 8080            # лендинг  -> http://127.0.0.1:8080
python3 cabinet_server.py 8081    # кабинет -> http://127.0.0.1:8081
```

- **Кабинет (8081):** `/` — хаб входа с кнопкой демо-режима, `/login`,
  `/register`, `/forgot-password`, `/app/` (SPA кабинета), `/admin/` (админка),
  весь `/api/*`. Лендинг здесь намеренно не отдаётся (404).
- **Сайт (8080):** лендинг + те же страницы кабинета (если нужен один порт).

Вход без регистрации: на хабе кабинета или на `/login` нажмите
**«🚀 Войти в демо-режиме»** (прямая ссылка `/login#demo`).

### Вход без регистрации (демо-режим)

На странице входа есть кнопка **«🚀 Войти в демо-режиме (без регистрации)»**
(также ссылка «Демо-кабинет без регистрации» в шапке лендинга и прямой адрес
`/login#demo`). Демо-аккаунт создаётся автоматически при первом запуске
сервера и уже содержит 2 проекта с анализом, 12 постов в разных статусах,
соцсети и платёж:

| Аккаунт | Пароль | Что это |
| --- | --- | --- |
| `demo@sociora.ru` | `demo1234` | обычный пользователь на тарифе Business |
| `admin@sociora.ru` | `admin1234` | администратор (доступ к `/admin/`) |

## Что умеет личный кабинет

| Раздел | Возможности |
| --- | --- |
| Обзор | статистика проектов/постов, подписка, баланс |
| Проекты | создание, «анализ ниши» (мок-ИИ предлагает темы), удаление |
| Посты | генерация, редактирование, перегенерация по комментарию, одобрение, публикация, удаление |

| Тарифы | Trial/Start/Pro/Business, пакеты постов, история платежей (демо-оплата) |
| Настройки | имя, тон голоса, смена пароля |

## API (кратко)

```
POST /api/register, /api/login, /api/logout, /api/settings, /api/settings/password
GET  /api/me
GET/POST/DELETE /api/projects, /api/projects/{id}, /api/projects/{id}/analyze
GET/POST /api/posts, /api/posts/generate, /api/posts/{id}, /api/posts/{id}/regenerate,
     /api/posts/{id}/status (approve/schedule/publish/draft), DELETE /api/posts/{id}
GET/POST/DELETE /api/socials
GET  /api/analytics?network=all|telegram|vk|max
GET/POST /api/tariffs, /api/tariffs/choose, /api/packs/buy, /api/payments
POST /api/plan/week
GET  /api/admin/stats, /api/admin/users, /api/admin/posts, /api/admin/payments
POST /api/admin/users/{id}   {action: block|plan|balance|admin, ...}
```

Аутентификация — три механизма одновременно (нужны все, чтобы кабинет
открывался в любом окружении):

1. заголовок `Authorization: Bearer <token>` — токен приходит в ответе
   `/api/login` и хранится в `localStorage`;
2. токен в hash URL (`/app/#token=…`) — fallback на случай, если
   `localStorage` недоступен (песочница iframe): hash переживает
   перезагрузку страницы и не уходит на сервер;
3. cookie `session_token` (HttpOnly) — когда прокси её пробрасывает.

Почему так: часть прокси вырезает `Set-Cookie`, а iframe-песочница может
заблокировать `localStorage` — при любом из этих сценариев сессия
продолжает работать. Пароли — PBKDF2-SHA256. Тарифные лимиты (проекты, соцсети, баланс постов)
проверяются на сервере; заблокированный пользователь не может войти (403).

### Админ-панель

`/admin/` (или кнопка «Админ-панель» в боковом меню кабинета — видна только
администратору). Умеет: сводную статистику, список пользователей с блокировкой,
сменой тарифа, начислением постов и выдачей прав админа, все посты и историю
платежей. У оригинала (sociora.ru) публичной админки нет — `/admin` отдаёт 404,
панель сделана для удобства владельца копии.

## Проверка работоспособности

```bash
python3 server.py 8080 &            # в одном терминале
python3 cabinet_server.py 8081 &    # в другом
python3 verify.py                   # сайт + кабинет на 8080
python3 verify_cabinet.py           # отдельный сервер кабинета на 8081
node tests_token.js                 # логика сессии (localStorage/hash/Bearer)
```

```
Итого: 111 проверок, пройдено 111, провалено 0
```

Проверяется: доступность 25 страниц и ассетов, внутренние ссылки и якоря,
структура (title/h1/description/cookie), интерактив лендинга, редиректы
`/app → /app/` и `/admin → /admin/`, наличие кнопки демо-входа и подключение
админки к API, а также **сквозной API-сценарий**: регистрация → отказ при
неверном пароле → проект → анализ → генерация (баланс 15→14) → одобрение →
публикация → перегенерация → соцсеть → лимит trial → аналитика → тариф Pro
(150 постов) → пакет (+100) → план на неделю → настройки → выход → 401 →
демо-вход → Bearer-авторизация без cookie → админ-статистика → 403 для
не-админа → 401 для гостя.

## Как это устроено

- **Мок-ИИ** (`server.py`): анализ ниши по ключевым словам (салон красоты,
  кофейня, фитнес, универсальный шаблон), генерация 10–15 тем и полноценных
  постов с рубриками, «перегенерация по комментарию».
- **Оплата тарифов** — демонстрационная: активирует план и начисляет посты,
  реальных списаний нет.
- **Публикация в соцсети** — демонстрационная: пост получает статус
  «опубликован» и стартовую статистику; реальные токены не используются.
- **База** — `data/app.db` (SQLite), создаётся при первом запуске; демо- и
  админ-аккаунты с образцами данных засеиваются автоматически (`seed_demo`).
- **Админ-панель** — отдельное SPA в `admin/`, доступно только пользователям с
  флагом `is_admin`; все `/api/admin/*` возвращают 403 обычным пользователям.

## Примечания

- Тексты юридических страниц воспроизведены из оригинала для демонстрации
  структуры; для боевого использования их нужно заменить своими.
- Яндекс.Метрика и сторонние скрипты не подключены — копия автономна.
- Кнопки поддержки ведут на реальный Telegram @sociora_support.
