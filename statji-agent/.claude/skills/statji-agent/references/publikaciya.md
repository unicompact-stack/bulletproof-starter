# Публикация и измерение

## Порядок

```bash
# 1. Проверки
python3 engine/qa.py content/articles/<slug>.md          # exit 0
python3 -m unittest discover -s engine/tests -v          # движок в порядке (если менял код)

# 2. Независимая приёмка вторым агентом (шаг 4б в SKILL.md) — без неё не идём дальше

# 3. Сборка сайта (без --approve статья не попадёт в сайт)
python3 engine/web.py build
python3 engine/web.py build --approve <slug>            # человек поставил одобрение

# 4. Посмотреть глазами
python3 engine/web.py serve --port 8000
# → главная, статья, страница замера, дашборд /dashboard.html

# 5. Отчёт
python3 engine/report.py
```

## Ссылки для распространения

В каждой статье есть поле `slug`. Ссылки строим так:

```
https://stroyceh12.ru/articles/<slug>/?ref=<slug>        # сайт
https://stroyceh12.ru/articles/<slug>/?ref=tg-<slug>     # перепубликация в Telegram/Дзен
```

`ref` — это то, что связывает заявку со статьёй. Ссылка без `ref` = потерянное измерение.
Заявки падают в `data/leads.jsonl`, в каждой — `ref`, время, канал.

## Что делать после публикации (10 минут)

1. Прочитать первый абзац вслух — не сбивается ли язык.
2. Проверить таблицу на телефоне — она должна уместиться.
3. Кликнуть кнопку «Вызвать замерщика» — форма должна открыться и отправить тестовую заявку.
4. Отправить ссылку с `?ref=` в свой чат — так начинается распространение.

## Расписание

| Когда | Что |
|---|---|
| 1 раз в неделю | новая статья (4 в месяц) |
| 1 раз в неделю | `python3 engine/report.py` — посмотреть, какие статьи дают заявки |
| 1 раз в месяц | ревизия `content/topics.md`: убрать темы без интента, добавить новые возражения из диалогов |
| 1 раз в 3 месяца | статья без заявок и без скроллов до оффера — переписать или снять |

## Чего не делать

- Не публиковать «на всякий случай» без QA и приёмки.
- Не менять `qa.py`, чтобы статья прошла.
- Не переписывать уже работающую статью ради «свежести» — это сбрасывает накопленный сигнал поиска.
- Не дублировать одну статью в пять каналов с одинаковым текстом.
