# Агент-статейник · СК «СтройЦех 12» (демо)

**Пилотный проект:** агент, который пишет статьи под поисковые запросы и приводит заявки
на бесплатный замер. Собран по методу «Понять → Выбрать → Спроектировать → Сделать → Принять».

> ⚠️ **Демо-данные.** Компания, цены, сроки, статистика и адрес сайта придуманы.
> Ничего отсюда нельзя выдавать за реальные факты о рынке ремонта в Йошкар-Оле.
> Ценность проекта — в методе и в работающем коде, а не в цифрах.

## Быстрый старт

```bash
cd statji-agent

python3 engine/qa.py --corpus                      # проверить все статьи
python3 engine/qa.py content/examples/_bad-example.md   # увидеть, как ловятся ошибки
python3 -m unittest discover -s engine/tests -v    # тесты движка (24)
python3 engine/web.py build                        # собрать сайт
python3 engine/web.py serve --port 8000            # сайт + приём заявок
python3 engine/report.py                           # отчёт владельцу
```

Открыть: `/` — статьи, `/zamer/` — замер, `/dashboard.html` — дашборд агента.

## Как работает агент (5 шагов)

1. **Понять, зачем статья.** Берёт одно возражение (O1–O7) и один целевой запрос.
   Не «интересная тема», а «человек боится, что его обманут по смете».
2. **Выбрать тему по приоритету.** Скоринг: коммерческий интент + деньги в запросе +
   частота + слабость конкурентов + какое возражение закрывает. Очередь — `content/topics.md`.
3. **Написать.** Ответ в первом абзаце, таблица цен или сроков, раздел «Как проверить»,
   один блок оффера. Все цифры — только из `content/facts.md`.
4. **Проверить.** Сначала машиной (`qa.py`), потом **вторым агентом** — он видит только спеку,
   статью и отчёт QA, без рассуждений автора. Самоприёмка запрещена контрактом.
5. **Опубликовать и измерить.** `build --approve <slug>` (решает человек), ссылка с `?ref=<slug>`,
   заявка падает в `data/leads.jsonl`, отчёт показывает, какая статья её принесла.

## Как он проверяет (12 кодов)

| Код | Что ловит | Пример из антипримера |
|---|---|---|
| **S** | битый frontmatter, несколько возражений | `objection: O1, O2, O3` |
| **T** | title/description/H1 вне лимитов | title 111 символов |
| **L** | объём вне 550–1100 слов | 213 слов |
| **K** | целевой запрос не в H1/первом абзаце/H2 | первый абзац — 0 % |
| **F** | **число, которого нет в реестре фактов** | «от 3 200 ₽ за м²», «90 000 ₽» |
| **O** | нет оффера или не ровно одна ссылка-призыв | ссылок на `/zamer/` нет вообще |
| **R** | юридический стоп-лист (ст. 5 ФЗ «О рекламе») | «лучшая», «самые низкие», «100 %», «навсегда» |
| **C** | структура: ≥3 H2, раздел «Как проверить», таблица, абзацы ≤ 90 слов | H2 нет, таблицы нет |
| **H** | «вода нейросети»: длинные предложения и слова | — (прошло) |
| **D** | дубли: пересечение по 5-словным шингам ≥ 15 % | 17,2 % с другой статьёй |
| **M** | битые внутренние ссылки, их не хватает | 0 ссылок |
| **X** | выдуманные кейсы и отзывы | «клиент Сергей», «клиентка Анна написала отзыв» |

Главное правило: **правится статья, а не порог проверки.**

## Как это приносит клиентов

```
поиск → статья (закрывает одно возражение) → оффер «замер + смета за 24 часа»
      → заявка с ?ref=<slug> → data/leads.jsonl → отчёт: какая статья сработала
```

Дашборд и `report.py` показывают заявки **по каждой статье**. Если данных нет — пишут
«неизвестно», а не ноль: это то же правило, что и в реестре фактов.

## Что проверено на этой итерации

- `qa.py --corpus` → **3/3 статьи pass**; антипример → **11 кодов из 12 fail, exit 1**.
- `unittest` → **24/24 ok** (тесты нашли 2 настоящих бага в движке: диапазоны вида
  «45–60 рабочих дней» и «Клиент Сергей» с заглавной буквы — оба исправлены в коде, не в тестах).
- Сайт собран и работает, форма заявки пишет в файл, валидация отклоняет заявку без телефона.
- Заявки привязываются к статье: в отчёте появилось «Лучшая статья по заявкам: kak-vybrat-podryadchika».

## Что осталось открытым

- **Реальные позиции в поиске** — вне проекта: нужен живой домен и 4–6 месяцев публикаций.
- **Время агента (65 мин)** — регламент, а не секундомер: замер появится, когда агент начнёт работать у вас.
- **Независимая приёмка вторым агентом** — процедура описана, но в этой песочнице я был один:
  роль приёмщика выполнил отдельный проход по чек-листу, а не отдельный агент. Это честная граница.
- **Внешняя публикация** (Дзен, VK) не автоматизирована намеренно: сначала сайт и измерение.

## Как перенести на свою нишу

1. Заполнить `.business/` под свой бизнес: оффер, аватар, возражения, воронка, экономика.
2. Переписать `content/facts.md` — **только настоящие цифры с источниками**.
3. Составить свою очередь тем в `content/topics.md` со скорингом.
4. Проверить пороги в `engine/qa.py` под свой формат (объём, число H2) — один раз, осознанно.
5. Дальше цикл: тема → черновик → `qa.py` → второй агент → `--approve` → отчёт.
