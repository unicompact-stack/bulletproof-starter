# План: агент-статейник (итерация 1)

**Спека:** [../specs/statji-agent.md](../specs/statji-agent.md) · **Режим:** normal, выходит в deep на пункте публикации

| # | Задача | Критерии | Файлы | Проверка |
|---|---|---|---|---|
| T1 | Бизнес-контекст (ниша, оффер, возражения, экономика) | C3, C4 | `.business/**` | читается человеком, ссылки внутри валидны |
| T2 | Реестр фактов с источниками | C2 | `content/facts.md` | каждое число имеет ID и источник |
| T3 | Скилл агента: отбор тем, правила текста, QA, публикация | C1–C9 | `.claude/skills/statji-agent/**` | чек-лист в SKILL.md совпадает с кодами QA |
| T4 | Движок проверки `qa.py` + тесты | C2, C5, C6, C7, C8 | `engine/qa.py`, `engine/tests/` | `unittest` зелёный; плохой пример валится |
| T5 | Сайт и приём заявок `site.py` | C4, C10 | `engine/web.py` | живая страница, заявка пишется в `leads.jsonl` |
| T6 | Очередь тем и 3 статьи | C3, C5, C8 | `content/topics.md`, `content/articles/*` | `qa.py` exit 0 по каждой |
| T7 | Отчёт владельцу `report.py` | C10 | `engine/report.py` | показывает заявки по статьям, иначе «неизвестно» |

## Порядок и зависимости

```
T1 → T2 → T3 → T4 → T6 → T5 → T7
                   ↘ (T5 можно параллельно с T6)
```

## Границы итерации

- Без деплоя наружу: сайт поднимается локально.
- Без автоматической публикации: `--approve` ставит человек.
- Одна ниша, один сайт. Никакой мультиарендности.

## Что проверяем в конце (приёмка)

1. `qa.py` на 3 хороших статьях — exit 0; на примере `_bad-example.md` — exit 1 с перечнем кодов.
2. `unittest` — все тесты зелёные.
3. Сайт: открывается, статья читается, форма пишет заявку, дашборд её показывает.
4. `report.py` — заявка привязана к slug статьи.

## Что останется открытым после итерации

- Реальный бэклинк-профиль и позиции в поиске — вне песочницы.
- Внешняя независимая приёмка живым агентом — выполняется человеком при первом запуске у себя.
