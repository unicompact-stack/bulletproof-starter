# CLAUDE.md — правила работы с агентом в проекте vk-agent

> **СТОП. Это правила для ИИ-агента, который помогает в этом подпроекте.**
> Прочитай их целиком перед первой правкой. Ниже — то, что нельзя нарушать никогда,
> и порядок работы. Правила важнее скорости.

## Что это за проект

Агент ведёт группу ВКонтакте про банковские продукты: собирает факты со страниц банков,
собирает посты по шаблонам, проверяет их механическими проверками и публикует после
подтверждения человеком. Подробности — в `SPEC.md` и `README.md`.

## Что нельзя нарушать

1. **Не публиковать без подтверждения.** Ни одной записи в ВК без явной команды человека
   (`--live` или галочка «боевой режим»). Это не «нужно уточнить», это запрет.
2. **Не выдумывать цифры.** Любая цифра в посте приходит из `knowledge/facts/<bank>.json`
   с датой и ссылкой на источник. Нет факта — пост помечается `needs-data` и не выходит.
   «Примерно 15%», «около 8 000 ₽», данные из памяти модели — запрещены.
3. **Не ослаблять проверки ради «чтобы пост прошёл».** Проверки — контракт проекта.
   Если проверка мешает — сначала обсудить с владельцем, потом менять; снятие проверки
   без обсуждения считается регрессом.
4. **Не добавлять зависимости npm.** Проект работает на стандартной библиотеке Node.
   Новая зависимость — только с явного согласия владельца.
5. **Не коммитить секреты и данные.** `.env`, `knowledge/facts/*.json`, `queue/*.json`,
   `data/*` — локальные, в git не едут (см. `.gitignore`).
6. **Не писать проценты в абзацах текста.** Числа живут в блоке фактов, где рядом стоит дата
   проверки. Иначе проверка `number-without-date` заблокирует пост.

## Порядок работы над задачей

1. **Прочитать `SPEC.md`** — что мы вообще строим и какие критерии готовности.
2. **Найти место правки.** Ориентир: разбор страниц — `src/parse.js`, сборка текста —
   `src/generate.js`, правила — `src/checks.js`, панель — `panel/page.html`, настройки —
   `config/`.
3. **Сначала тест или фикстура.** Для парсера — страница в `test/fixtures/banks/` и случай
   в `test/parse.test.js`. Для проверок — случай в `test/checks.test.js`. Красный тест,
   потом зелёный.
4. **Прогнать `npm test`** — 48 тестов должны быть зелёными до того, как сказать «готово».
5. **Прогнать конвейер руками** на фикстурах, без интернета:
   ```bash
   npm run fetch -- --bank tbank --offline
   npm run generate -- --bank tbank --rubric karta
   npm run preview
   ```
6. **Отчитаться честно:** что проверено, что нет. Если что-то не смог проверить (нет сети,
   нет ключа ВК) — сказать прямо, а не молчать.

## Что где лежит

| Задача | Файлы |
|---|---|
| Новый банк | `config/banks.json`, `knowledge/banks/<id>.md` |
| Новая рубрика | `config/rubrics.json`, `config/hooks.json`, `config/bodies.json`, `templates/<id>.md` |
| Новая тема журнала | `knowledge/journal/<nn>-<slug>.md` |
| Новый источник парсинга | `sources` в `config/banks.json` + разбор в `src/parse.js` |
| Новая проверка | `src/checks.js` + `test/checks.test.js` |
| Формулировки | `config/hooks.json` (хук и призыв), `config/bodies.json` (лид и абзацы) |

## Стиль кода

- Только стандартная библиотека Node 20+, ESM (`import`/`export`)
- Комментарии и тексты интерфейса — по-русски, простым языком, без канцелярита
- Ошибки формулируются так, чтобы человек понял, что делать: не «invalid input»,
  а «Банк не найден: «сбер». Список — config/banks.json»
- Каждая функция проверок возвращает объект с `id` и `message` — сообщение видит человек
- Детерминизм обязателен: один и тот же вход даёт один и тот же текст. Никаких `Math.random`
  и текущего времени в текстах (время можно в датах, но не в выборе формулировок)

## Команды проекта

```bash
npm test                                    # 48 тестов
npm run fetch -- --bank tbank --offline     # сбор фактов без интернета
npm run generate -- --bank tbank --rubric karta
npm run checks                              # состояние очереди
npm run preview                             # панель на http://localhost:4321
npm run publish -- --id <id>                # сухой прогон (без --live ничего не уходит)
npm run status                              # проверка ключа ВК
```

## Когда останавливаться и спрашивать

- Нужно снять или ослабить проверку
- Нужна новая зависимость или платный ключ
- Правка касается того, что уходит читателю (тексты оговорок, дисклеймеры, маркировка рекламы)
- Хочется поменять формулировку в `config/stopwords.json` (это правовой контур, а не контент)
