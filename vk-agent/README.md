# VK Agent — агент для ведения группы ВКонтакте

Агент, который сам понимает, о чём пост, и собирает его без участия человека: берёт банк,
достаёт актуальные цифры со страниц банка, накладывает их на структуру темы из журнала и кладёт
готовый текст на витрину. Дальше — один клик: опубликовать или переделать.

Первый шаг — **технический каркас**: цифры, структура, проверки, панель, публикация.
Генерация формулировок нейросетью подключается вторым шагом поверх этого каркаса
(см. [docs/AI-STEP.md](docs/AI-STEP.md)).

---

## Что уже работает, а что нет

**Работает:**

- Сбор фактов со страниц банков: проценты, суммы, сроки, даты, новости. Онлайн — с сайтов банков,
  офлайн — на фикстурах из `test/fixtures/`
- Сборка поста: банк + рубрика + тема журнала + факты → текст с датами проверки рядом с цифрами
- 14 механических проверок перед публикацией (запрещённые обещания, цифры без даты, оговорки,
  повтор поста, ссылки и др.)
- Панель превью в браузере: собрал → посмотрел → поправил руками → опубликовал
- Публикация в сообщество через API ВК, включая отложенные записи. По умолчанию — сухой прогон
- 48 тестов на парсер, сборку, проверки и публикацию

**Ещё нет (честно):**

- Формулировки собираются по шаблонам, а не нейросетью. Текст читается ровно, но это каркас,
  а не живой автор
- Картинок нет: пост текстовый
- Автопостинга по расписанию из планировщика нет — публикация запускается руками (кнопкой или командой)
- Второй, проверяющий, агент не написан. Его роль пока закрывают механические проверки
- Данные проверены только на фикстурах: в песочнице, где это собиралось, нет доступа к сайтам банков
  и к API ВК. Первый прогон на своём компьютере может вскрыть пары селекторов — см. «Если парсер
  ничего не нашёл» ниже

## Быстрый старт

Нужен **Node.js 20+** (проверено на 22). Зависимостей нет вообще — только стандартная библиотека.

```bash
cd vk-agent
cp .env.example .env      # заполнить VK_TOKEN и VK_GROUP_ID (см. ниже)

npm run fetch -- --bank alfa --offline     # посмотреть, как работает разбор данных
npm run generate -- --bank alfa --rubric karta
npm run preview                            # панель в браузере: http://localhost:4321
```

Первый прогон без интернета: `--offline` разбирает тестовые фикстуры, чтобы можно было увидеть
весь конвейер, не выходя в сеть.

### Ключ ВКонтакте

1. Управление сообществом → **Настройки** → **Работа с API** → **Создать ключ**
2. Права: **Управление сообществом** + **Записи на стене** (для фото позже — ещё «Фотографии»)
3. Скопировать ключ в `.env` → `VK_TOKEN`
4. В `VK_GROUP_ID` — число из адреса сообщества (`vk.com/club123456` → `123456`, без минуса)
5. Проверить: `npm run status` — покажет название группы и права ключа

Публикация всегда идёт в два шага: сначала сухой прогон (`npm run publish -- --id <id>`),
и только с флагом `--live` текст реально уходит в ВК.

## Как это работает

```
config/banks.json ──► fetch ──► knowledge/facts/<bank>.json
                                        │
config/rubrics.json  ─┐                 │
knowledge/journal/*  ─┼──► generate ────┴──► queue/<id>.json ──► проверки ──► панель/CLI ──► publish ──► ВК
config/hooks.json    ─┤                                                                        (dry-run по умолчанию)
config/bodies.json   ─┤
templates/*.md       ─┘
```

Главное правило: **цифра без даты и источника в пост не попадает**. Поэтому у каждого факта есть
`date` и `source`, а в тексте дата стоит рядом с цифрой — «Кэшбэк — до 15% (проверено 16.09.2026)».
Если данных не хватает, пост помечается `needs-data` и публикация блокируется: агент не выдумывает
ставки и не переносит цифры из головы.

Второе правило: **проверки — это код, а не мнение**. Каждая проверка воспроизводима: одна и та же
цифра без даты всегда даёт одну и ту же ошибку.

## Команды

| Команда | Что делает |
|---|---|
| `npm run fetch -- --bank alfa [--offline] [--all]` | Собрать факты со страниц банка |
| `npm run generate -- --bank alfa --rubric karta [--variant 1] [--topic ...]` | Собрать пост |
| `npm run topic -- --bank alfa --rubric karta` | Показать, какая тема журнала будет взята |
| `npm run checks [--id <id>]` | Состояние очереди и разбор проверок |
| `npm run preview` | Панель превью в браузере |
| `npm run publish -- --id <id> [--live] [--schedule 2026-10-05T10:00]` | Публикация (без `--live` — сухой прогон) |
| `npm run status` | Ключ ВК, права, база фактов |
| `npm test` | 48 тестов |

Рубрики: `karta` (дебетовая карта), `kreditka` (кредитная карта), `vklad` (вклад или накопительный
счёт), `akciya` (акция), `novost` (новость). Банки задаются в `config/banks.json`.

Команда понимает свободный текст: `npm run generate -- --bank alfa "размести пост про вклад"`
определит рубрику по словам.

## Панель превью

`npm run preview` поднимает страницу на `http://localhost:4321`. Что там есть:

- выбор банка, рубрики и темы, кнопка **Собрать пост**
- превью в виде записи ВК: как пост будет выглядеть в ленте
- **список проверок**: что блокирует, что просто предупреждает
- правка текста руками — проверки перезапускаются после правки
- **Переделать** — тот же пост с другим хуком и другими абзацами (меняется вариант)
- **Опубликовать** — сухой прогон, а с галочкой «боевой режим» — реальная публикация
- таблица фактов банка с датами: видно, что устарело
- кнопка **Обновить факты** (онлайн) и **Факты из фикстур** (офлайн)

## Проверки перед публикацией

| Проверка | Реакция |
|---|---|
| Нет обязательных фактов для рубрики | блок: `needs-data` |
| Незаполненная вставка в тексте (`{факт}`) | блок |
| Цифра с процентом или рублями без даты проверки | блок |
| Запрещённые формулировки («гарантированный доход», «одобрят всем») | блок |
| Нет обязательной оговорки для типа продукта | блок |
| Пост помечен рекламой, но маркировки нет | блок |
| У факта нет даты | блок |
| Пост короче 200 или без заголовка/фактов | блок |
| Факт старше `FACT_TTL_DAYS` (30 дней) | предупреждение |
| Похожий пост выходил меньше недели назад | предупреждение |
| Меньше двух или больше пяти хештегов | предупреждение |
| Внешняя ссылка (ВК снижает охват) | предупреждение |
| Ссылка на сторонний домен | предупреждение |
| Задвоенное слово, крик капсом, много «!» | предупреждение |
| Спорные формулировки («самый выгодный») | предупреждение |

Список запрещённых и спорных формулировок — `config/stopwords.json`. Обязательные оговорки —
`config/disclaimers.json`.

## Как расширять

| Что добавить | Куда |
|---|---|
| Новый банк | `config/banks.json` (id, название, псевдонимы, ссылки, источники) + `knowledge/banks/<id>.md` |
| Новую рубрику | `config/rubrics.json`, `config/hooks.json`, `config/bodies.json`, `templates/<id>.md` |
| Новую тему для журнала | новый файл в `knowledge/journal/` — с front-matter `topic_id`, `title`, `rubrics` |
| Новую проверку | функция в `src/checks.js` + случай в `test/checks.test.js` |
| Новый источник парсинга | `sources` у банка в `config/banks.json` (`extract: percents \| text`) |

### Если парсер ничего не нашёл

Страницы банков меняются, и селекторы придётся подкручивать. Порядок такой:

1. `npm run fetch -- --bank alfa` — в отчёте видно, какой источник вернул сколько фактов
2. Скачанная страница остаётся в `data/cache/alfa-cards.html` — по ней видно, что реально на странице
3. Правится разбор в `src/parse.js` (`factsFromProductPage`), правило проверяется тестом на фикстуре
   в `test/fixtures/banks/` и командой `npm test`

## Правовой минимум

Это не юридическая консультация, а список того, о чём нельзя забывать в этой теме. Если публикации
оплачивает банк или партнёрская сеть — перед запуском стоит показать схему юристу.

**Реклама финансовых услуг** (ст. 28 ФЗ «О рекламе»):

- в рекламе банковских услуг должно быть **наименование лица, оказывающего услугу** — поэтому в
  каждом посте есть название банка и ссылка на его сайт
- если указано **хотя бы одно условие**, влияющее на доходы или расходы клиента, нельзя умалчивать
  об остальных таких условиях: кэшбэк без лимита, ставка без срока и суммы — типичное нарушение
  ([разбор статьи 28](https://www.law.ru/question/127335-soglasno-fz-o-reklame-statya-28-reklama-finansovyh-uslug-i-finansovoy-deyatelnosti),
  [практика ФАС](https://br.fas.gov.ru/to/lipetskoe-ufas-rossii/10-fb648db2-7e59-4623-994c-4ea414ce9f9b/))
- нельзя содержать **гарантии доходности** — отсюда `config/stopwords.json` и блокировка поста
  с фразой «гарантированный доход»

Именно ради этих пунктов в агенте появились обязательные факты по рубрике (`required_facts`),
оговорки по типу продукта и запрет на цифры без даты.

**Маркировка рекламы** (ст. 18.1 ФЗ «О рекламе», ст. 14.3 КоАП):

- если пост — реклама, нужны **три элемента**: пометка «Реклама», данные о рекламодателе (наименование
  или ФИО, ИНН, ОГРН) и токен **ERID**, полученный через ОРД
  ([требования и штрафы](https://aldushin.ru/blog/markirovka-reklamy-v-internete-2026),
  [обзор 2026](https://ria.ru/20250316/markirovka-1896148209.html))
- маркировка нужна и когда денег нет: бартер, «по-дружески», промокод, реферальная ссылка
- ERID должен быть читаемым: мелкий или скрытый токен = отсутствие маркировки
- штрафы: за отсутствие пометки «Реклама» или данных рекламодателя — от 2 000 ₽ для физлица,
  за рекламу в интернете без ERID — от 30 000 ₽

В агенте это отражено так: у поста есть флаг «реклама», без маркировки он не публикуется,
а для рубрики «акция» проверка напоминает про ERID.

## Ограничения, о которых надо знать

- **Парсер — это эвристика.** Он ищет проценты и суммы рядом с ключевыми словами на строке. Если банк
  переверстал страницу, разбор может найти не ту цифру. Защита — дата и источник у каждого факта,
  обязательные факты по рубрике и тесты на фикстурах. Для важных цифр всё равно стоит заглядывать
  в источник: он лежит в факте как `source`
- **Шаблонный текст однообразен.** Хуки и абзацы конечны — при частых постах это будет заметно.
  Лечится подключением нейросети (следующий шаг) и расширением `config/hooks.json`
- **Автопостинга нет.** Публикация запускается руками. Это осознанно: пока проверок мало, автомат
  без присмотра — лишний риск
- **Один аккаунт, одно сообщество.** Мультиаккаунт и параллельные площадки — в планах

## Структура

```
vk-agent/
├── README.md              ← ты здесь
├── SPEC.md                ← что строим и критерии готовности
├── .env.example           ← шаблон настроек (ключ ВК, порт, сроки)
├── config/                ← банки, рубрики, хуки, абзацы, оговорки, стоп-слова
├── templates/             ← шаблоны постов по рубрикам
├── knowledge/
│   ├── banks/             ← заметки о банках (что можно и нельзя писать)
│   ├── journal/           ← темы постов: идея, структура, что нельзя
│   └── facts/             ← собранные цифры с датами и источниками
├── src/                   ← код: сбор, разбор, сборка, проверки, панель, публикация
├── panel/page.html        ← панель превью
├── test/                  ← тесты и фикстуры страниц банков
├── queue/                 ← черновики постов
└── docs/                  ← устройство, план, подключение ИИ
```
