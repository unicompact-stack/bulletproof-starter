# Content Agent — агент контента для соцсетей

Агент, который сам понимает, о чём пост, и собирает его без участия человека: берёт объект,
достаёт актуальные цифры с его страниц, накладывает их на структуру темы из журнала и кладёт
готовый текст на витрину. Дальше — один клик: опубликовать или переделать.

Агент **не привязан к банкам и не привязан к ВКонтакте**. Банки — первая тематика, ВК — первая
площадка. На втором шаге та же самая механика уже работает на вакансиях; площадки Telegram и Дзен
описаны в реестре и ждут адаптеров.

```
Тематика (что пишем)                     Площадки (куда пишем)
profiles/banks/      → банки              channels/channels.json → ВК (работает)
profiles/vacancies/  → вакансии                            → Telegram (заглушка)
                                                          → Дзен (заглушка)
```

---

## Что уже работает, а что нет

**Работает:**

- **Две тематики.** Переключается одной настройкой `PROFILE=...`: вместе с ней меняются объекты,
  рубрики, формулировки, оговорки, стоп-слова, разбор страниц и база фактов
- Сбор фактов со страниц: проценты, суммы, сроки, даты, новости. Онлайн — с сайтов, офлайн —
  на фикстурах из `test/fixtures/<тематика>/`
- Сборка поста: объект + рубрика + тема журнала + факты → текст с датами проверки рядом с цифрами
- 15 механических проверок перед публикацией и проверка лимита длины площадки
- Панель превью в браузере: собрал → посмотрел → поправил руками → опубликовал
- Публикация одного поста на несколько площадок одной командой, включая отложенные записи.
  По умолчанию — сухой прогон
- 76 тестов на разбор, сбор, проверки, публикацию, тематики и площадки

**Ещё нет (честно):**

- Формулировки собираются по шаблонам, а не нейросетью. Текст читается ровно, но это каркас,
  а не живой автор
- Telegram и Дзен — заглушки: адаптеров нет. Включить их нельзя, и в сухом прогоне они честно
  помечены как «ушло бы», а в боевом режиме падают с ошибкой
- Картинок нет: пост текстовый
- Автопостинга по расписанию из планировщика нет — публикация запускается руками
- Живой публикации не было: в песочнице, где это собиралось, нет доступа к сайтам и к API ВК.
  Первый прогон на своём компьютере может вскрыть пары селекторов — см. «Если парсер ничего не нашёл»
- Агента уровнем выше (надзор за деньгами) нет — он только спроектирован,
  см. [docs/AGENT-ABOVE.md](docs/AGENT-ABOVE.md)

## Быстрый старт

Нужен **Node.js 20+** (проверено на 22). Зависимостей нет вообще — только стандартная библиотека.

```bash
cd vk-agent
cp .env.example .env      # заполнить VK_TOKEN и VK_GROUP_ID (см. ниже)

npm run profiles                              # какие тематики и площадки доступны
npm run fetch -- --subject alfa --offline    # посмотреть, как работает разбор данных
npm run generate -- --subject alfa --rubric karta
npm run preview                               # панель: http://localhost:4321
```

Первый прогон без интернета: `--offline` разбирает тестовые фикстуры, чтобы можно было увидеть
весь конвейер, не выходя в сеть.

### Вторая тематика

```bash
PROFILE=vacancies npm run fetch -- --all --offline
PROFILE=vacancies npm run generate -- --subject bystro --rubric vakansiya
PROFILE=vacancies npm run preview        # та же панель, но про вакансии
```

Тематику можно задавать и флагом: `npm run generate -- --profile vacancies --subject bystro --rubric vakansiya`.

### Ключ ВКонтакте

1. Управление сообществом → **Настройки** → **Работа с API** → **Создать ключ**
2. Права: **Управление сообществом** + **Записи на стене**
3. Скопировать ключ в `.env` → `VK_TOKEN`
4. В `VK_GROUP_ID` — число из адреса сообщества (`vk.com/club123456` → `123456`, без минуса)
5. Проверить: `npm run status` — покажет название группы и права ключа

Публикация всегда идёт в два шага: сначала сухой прогон (`npm run publish -- --id <id>`),
и только с флагом `--live` текст реально уходит.

## Как это работает

```
profiles/<т>/subjects.json ──► fetch ──► data/<т>/facts/<объект>.json
                                            │
profiles/<т>/rubrics.json  ─┐               │
profiles/<т>/journal/*     ─┼──► generate ──┴──► queue/<т>/<id>.json ──► проверки ──► панель/CLI ──► publish ──► площадки
profiles/<т>/hooks.json    ─┤                                                                      (dry-run по умолчанию)
profiles/<т>/bodies.json   ─┤
profiles/<т>/templates/*   ─┘
```

Главное правило: **цифра без даты и источника в пост не попадает**. Поэтому у каждого факта есть
`date` и `source`, а в тексте дата стоит рядом с цифрой — «Кэшбэк — до 15% (проверено 16.09.2026)».
Если данных не хватает, пост помечается `needs-data` и публикация блокируется: агент не выдумывает
ставки и не переносит цифры из головы.

Второе правило: **проверки — это код, а не мнение**. Одна и та же цифра без даты всегда даёт
одну и ту же ошибку.

Третье правило: **площадка, чей адаптер не написан, не притворяется рабочей**. Иначе получится
пост «опубликован», а его никто не видел.

## Команды

| Команда | Что делает |
|---|---|
| `npm run profiles` | Список тематик и площадок |
| `npm run fetch -- --subject alfa [--offline] [--all]` | Собрать факты со страниц объекта |
| `npm run generate -- --subject alfa --rubric karta [--variant 1]` | Собрать пост |
| `npm run topic -- --rubric karta` | Показать, какая тема журнала будет взята |
| `npm run checks [--id <id>]` | Состояние очереди и разбор проверок |
| `npm run preview` | Панель превью в браузере |
| `npm run publish -- --id <id> [--live] [--channels vk,telegram]` | Публикация (без `--live` — сухой прогон) |
| `npm run status` | Готовность площадок, ключи, база фактов |
| `npm test` | 76 тестов |

Общие флаги: `--profile <id>` — тематика; `PROFILE=<id>` в `.env` — то же самое постоянно.

**Тематика `banks`:** рубрики `karta` (дебетовая карта), `kreditka` (кредитная карта), `vklad`
(вклад или накопительный счёт), `akciya` (акция), `novost` (новость). Банки — в
`profiles/banks/subjects.json`.

**Тематика `vacancies`:** рубрики `vakansiya`, `usloviya`, `novost`. Работодатели — в
`profiles/vacancies/subjects.json`.

Команда понимает свободный текст: `npm run generate -- --subject alfa "размести пост про вклад"`
определит рубрику по словам.

## Панель превью

`npm run preview` поднимает страницу на `http://localhost:4321`. Что там есть:

- выбор тематики (если их несколько), объекта, рубрики и темы, кнопка **Собрать пост**
- превью в виде записи ВК: как пост будет выглядеть в ленте
- **список проверок**: что блокирует, что просто предупреждает
- правка текста руками — проверки перезапускаются после правки
- **Переделать** — тот же пост с другим хуком и другими абзацами (меняется вариант)
- **Опубликовать** — сухой прогон по всем включённым площадкам, а с галочкой «боевой режим» —
  реальная публикация. Можно выбрать одну площадку вместо всех
- таблица фактов с датами: видно, что устарело
- кнопка **Обновить факты** (онлайн) и **Факты из фикстур** (офлайн)

## Проверки перед публикацией

| Проверка | Реакция |
|---|---|
| Нет обязательных фактов для рубрики | блок: `needs-data` |
| Незаполненная вставка в тексте (`{факт}`) | блок |
| Цифра с процентом или рублями без даты проверки | блок |
| Запрещённые формулировки («гарантированный доход», «одобрят всем») | блок |
| Нет обязательной оговорки для типа продукта | блок |
| Пост помечен рекламой, но маркировки нет | блок |
| У факта нет даты | блок |
| Пост короче 200 или без заголовка/фактов | блок |
| Текст длиннее лимита площадки | блок |
| Факт старше `FACT_TTL_DAYS` (30 дней) | предупреждение |
| Похожий пост выходил меньше недели назад | предупреждение |
| Меньше двух или больше пяти хештегов | предупреждение |
| Внешняя ссылка (ВК снижает охват) | предупреждение |
| Ссылка на сторонний домен | предупреждение |
| Задвоенное слово или фраза, крик капсом, много «!» | предупреждение |
| Спорные формулировки («самый выгодный») | предупреждение |
| Рубрика обычно платная — напоминание про маркировку и ERID | предупреждение |

Стоп-слова и обязательные оговорки — **у каждой тематики свои**:
`profiles/<т>/stopwords.json` и `profiles/<т>/disclaimers.json`. Общих списков нет намеренно:
«гарантированный доход» плох и в вакансии, и во вкладе, но «пассивный доход» в вакансии
не имеет смысла, а в инвестициях — имеет.

## Как расширять

| Что добавить | Куда |
|---|---|
| Новую тематику | `profiles/<т>/` + `src/extractors/<т>.js` — код конвейера не меняется |
| Новый объект (банк, работодатель) | `profiles/<т>/subjects.json` + заметка в `profiles/<т>/knowledge/<id>.md` |
| Новую рубрику | `rubrics.json`, `hooks.json`, `bodies.json`, `templates/<id>.md` |
| Новую тему для журнала | новый файл в `profiles/<т>/journal/` с front-matter `topic_id`, `title`, `rubrics` |
| Новую площадку | `src/channels/<п>.js` + запись в `channels/channels.json` |
| Новую проверку | функция в `src/checks.js` + случай в `test/checks.test.js` |
| Новый источник парсинга | `sources` у объекта в `profiles/<т>/subjects.json` |

Пошаговые инструкции — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### Если парсер ничего не нашёл

Страницы меняются, и селекторы придётся подкручивать. Порядок такой:

1. `npm run fetch -- --subject alfa` — в отчёте видно, какой источник вернул сколько фактов
2. Скачанная страница остаётся в `data/<т>/cache/<объект>-<источник>.html` — по ней видно, что
   реально на странице
3. Правится `src/extractors/<т>.js`, правило проверяется тестом на фикстуре в
   `test/fixtures/<т>/` и командой `npm test`

## Правовой минимум

Это не юридическая консультация, а список того, о чём нельзя забывать. Если публикации
оплачивает партнёр — перед запуском стоит показать схему юристу.

**Реклама финансовых услуг** (ст. 28 ФЗ «О рекламе»):

- в рекламе банковских услуг должно быть **наименование лица, оказывающего услугу** — поэтому в
  каждом посте есть название банка и ссылка на его сайт
- если указано **хотя бы одно условие**, влияющее на доходы или расходы клиента, нельзя умалчивать
  об остальных таких условиях: кэшбэк без лимита, ставка без срока и суммы — типичное нарушение
  ([разбор статьи 28](https://www.law.ru/question/127335-soglasno-fz-o-reklame-statya-28-reklama-finansovyh-uslug-i-finansovoy-deyatelnosti),
  [практика ФАС](https://br.fas.gov.ru/to/lipetskoe-ufas-rossii/10-fb648db2-7e59-4623-994c-4ea414ce9f9b/))
- нельзя содержать **гарантии доходности** — отсюда стоп-слова и блокировка поста с фразой
  «гарантированный доход»

**Маркировка рекламы** (ст. 18.1 ФЗ «О рекламе», ст. 14.3 КоАП):

- если пост — реклама, нужны **три элемента**: пометка «Реклама», данные о рекламодателе
  (наименование или ФИО, ИНН, ОГРН) и токен **ERID**, полученный через ОРД
  ([требования и штрафы](https://aldushin.ru/blog/markirovka-reklamy-v-internete-2026),
  [обзор 2026](https://ria.ru/20250316/markirovka-1896148209.html))
- маркировка нужна и когда денег нет: бартер, «по-дружески», промокод, реферальная ссылка
- ERID должен быть читаемым: мелкий или скрытый токен = отсутствие маркировки
- штрафы: за отсутствие пометки «Реклама» или данных рекламодателя — от 2 000 ₽ для физлица,
  за рекламу в интернете без ERID — от 30 000 ₽

В агенте это отражено так: у поста есть флаг «реклама», без маркировки он не публикуется,
а рубрики, которые обычно платные, помечены в профиле флагом `ads_check` — по ним приходит
напоминание про ERID.

**Вакансии:** если за отклик платят, пост считается рекламой услуги, даже если деньги не
платили напрямую. В рубрике `vakansiya` напоминание о маркировке включается автоматически.

## Ограничения, о которых надо знать

- **Парсер — это эвристика.** Он ищет проценты и суммы рядом с ключевыми словами. Если сайт
  переверстали, разбор может найти не ту цифру. Защита — дата и источник у каждого факта,
  обязательные факты по рубрике и тесты на фикстурах. Для важных цифр стоит заглядывать
  в источник: он лежит в факте как `source`
- **Шаблонный текст однообразен.** Хуки и абзацы конечны — при частых постах это будет заметно.
  Лечится подключением нейросети ([docs/AI-STEP.md](docs/AI-STEP.md)) и расширением `hooks.json`
- **Автопостинга нет.** Публикация запускается руками. Это осознанно: пока проверок мало,
  автомат без присмотра — лишний риск
- **Текст под разные площадки пока один.** Различаются только лимиты длины; разметка и ссылки
  под Telegram и Дзен не проработаны
