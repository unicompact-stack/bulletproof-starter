# SPEC — агент контента для соцсетей

**Статус:** технический каркас готов; живая публикация и живой парсер не проверены (нет сети в среде сборки)

## 1. Задача

Агент, который по короткой команде («пост про карты», «вакансия курьера») сам определяет тему,
собирает проверенные цифры, готовит текст и выкладывает его в соцсети. Человек смотрит результат
и нажимает «Опубликовать».

## 2. Границы

**Входит:**

- сбор фактов со страниц объектов тематики
- сборка поста по шаблонам с датой проверки рядом с каждой цифрой
- механические проверки перед публикацией
- панель превью и публикация по кнопке
- несколько тематик и несколько площадок

**Не входит (этапом раньше или позже):**

- нейросеть в цикле сборки — только формулировки, по `docs/AI-STEP.md`
- картинки
- автоматическое расписание без участия человека
- агент уровнем выше (надзор за деньгами) — по `docs/AGENT-ABOVE.md`
- юридическая экспертиза: проект содержит технические меры, а не юридическое заключение

## 3. Ключевые решения

| Решение | Почему |
|---|---|
| Тематика в настройках (`profiles/<id>/`), а не в коде | Владелец меняет тему работы без правки программы: сегодня банки, завтра вакансии |
| Площадки в реестре (`channels/channels.json`) с адаптерами | Сегодня ВК, завтра Telegram и Дзен — и один пост уходит на все |
| Никаких npm-зависимостей | Проект должен открываться и работать через год; зависимостей нечего обновлять |
| Свой разбор HTML на регулярках | У банка и вакансии разные смысловые единицы — это код, а не JSON-правила. Общие примитивы вынесены отдельно, тематическое — в свой файл |
| Цифра только из базы фактов, с датой и источником | Ст. 28 ФЗ «О рекламе»: нельзя умалчивать об условиях, влияющих на доходы и расходы |
| Проверки в коде, а не в голове модели | Одна и та же цифра без даты всегда даёт одну и ту же ошибку |
| Площадка без адаптера падает с ошибкой | Иначе пост «опубликован», а его никто не видел |
| Публикация по умолчанию — сухой прогон | Полуавтомат: решение о выходе всегда за человеком |
| Данные тематик в отдельных папках | Факты банков физически не могут попасть в пост про вакансию |

## 4. Критерии готовности

| # | Критерий | Состояние |

| 3 | Цифра в посте всегда рядом с датой проверки | ✅ проверка `number-without-date` |
| 4 | Нет данных → `needs-data`, публикация заблокирована | ✅ |

## 5. Риски

| Риск | Что делаем |
|---|---|
| Парсер не узнает перевёрстанную страницу | Дата и источник у каждого факта, кэш страниц, тесты на фикстурах, `FACT_TTL_DAYS` |
| Формулировки станут однообразными | Ротация хуков, а затем нейросеть по `docs/AI-STEP.md` |
| Универсальность размоет качество | Общий только каркас; формулировки, оговорки и стоп-слова у каждой тематики свои |
| Публикация без маркировки рекламы | Флаг `ads` блокирует пост без пометки; рубрики с флагом `ads_check` дают напоминание про ERID |
| Площадка-пустышка примет пост молча | Заглушка обязана падать; это проверяется тестом |

## 6. Что должно случиться дальше

1. Живой прогон: сбор фактов с настоящих сайтов, сверка глазами, публикация в тестовое сообщество
2. Нейросеть для формулировок — начиная с факт-чекера
3. Агент уровнем выше, когда наберётся история за месяц
4. Площадки Telegram и Дзен
