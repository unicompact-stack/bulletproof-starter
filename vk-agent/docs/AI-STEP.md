# Следующий шаг: подключить нейросеть к формулировкам

Каркас уже разделяет две вещи, которые нельзя смешивать: **что сказать** (факты с датами
и структурой) и **как сказать** (формулировки). Нейросеть подключается только ко второй части.
Цифры она не трогает вообще.

## Где именно точка подключения

Сейчас в `src/generate.js` три места собирают текст:

1. `fillFacts(hookPattern.text, available)` — хук
2. `fillFacts(paragraph, available)` — абзацы
3. `render(template, ...)` — финальная сборка по шаблону рубрики

Нейросеть заменяет пункты 1 и 2: вместо подстановки в готовую фразу она пишет хук и абзацы
по данным фактов. Пункт 3 (шаблон) остаётся: заголовок, блок цифр с датами, оговорка, хештеги —
это жёсткая рамка, которую менять нельзя.

## Контракт с моделью

**Вход** — JSON, ничего лишнего:

```json
{
  "bank_name": "Т-Банк",
  "rubric_name": "Дебетовая карта",
  "topic_title": "Как выбрать карту",
  "topic_structure": "1. Хук про разницу между рекламной и реальной цифрой\n2. Чек-лист...",
  "tone": "энергично и просто, конкретные цифры, без давления",
  "facts": [
    { "label": "Кэшбэк", "value": "до 15%", "date": "16.09.2026" },
    { "label": "Обслуживание", "value": "бесплатно, если покупки от 5 000 ₽ в месяц", "date": "16.09.2026" }
  ],
  "forbidden": ["гарантированный доход", "самый выгодный"],
  "length_target": "600-1200 символов",
  "output_shape": { "hook": "...", "paragraphs": ["...", "..."] }
}
```

**Выход** — только JSON той же формы: `hook`, `paragraphs`. Никаких цифр, которых нет во входных
фактах, никаких ссылок, никаких новых обещаний.

## Правила, которые нельзя обойти (и как это проверять)

1. **Цифра из воздуха = блок.** После генерации прогоняется факт-чекер: из текста вытаскиваются
   все числа (проценты и рубли), и каждое должно быть либо значением из `facts`, либо числом без
   денежного смысла (год, «3 шага»). Незнакомое число — пост не собирается.
   *Где делать:* новая проверка в `src/checks.js` (`number-not-in-facts`), случай в `test/checks.test.js`
2. **Все проверки остаются.** Текст от модели идёт в тот же `runChecks`. Никаких «модель умная,
   проверим потом»
3. **Стоп-слова и оговорки не отдаются модели на усмотрение.** Дисклеймер подставляет код,
   а не модель
4. **Не получилось — не публикуем.** Если модель вернула не JSON, лишние числа или пустой текст —
   откат на шаблон (текущее поведение). Пост с ошибкой лучше не показывать вообще

## Два способа подключения

**А. Без отдельного ключа — Claude Code в headless-режиме.**
Работает на подписке Claude: `claude -p "<промпт>" --output-format json`. Подходит, если постов
мало (1-3 в день) и хочется без оплаты за токены. Минус — нужен установленный Claude Code
и он завязан на одну машину.

**Б. Ключ к API в `.env`.**
`LLM_PROVIDER=anthropic|openai|gemini`, `LLM_API_KEY=...`, `LLM_MODEL=...`. Стабильнее,
работает на сервере, считается за токены. В обоих случаях новый модуль — `src/write.js`
с единственной функцией `writePost(input) → {hook, paragraphs}` и флагом `WRITER=template|llm`
в `.env`, чтобы можно было в любой момент вернуться к шаблонам.

## Порядок внедрения

1. Написать факт-чекер (`number-not-in-facts`) **до** подключения модели и убедиться,
   что текущие шаблонные посты его проходят
2. Вынести в `src/write.js` текущий шаблонный сборщик — без изменения поведения (тесты зелёные)
3. Добавить реализацию `llm` рядом, за тем же интерфейсом; сравнивать на одних и тех же фактах
4. Прогнать 10-20 постов в панели, посмотреть глазами, отобрать удачные формулировки в
   `config/hooks.json` — так модель постепенно учит проект, а не наоборот
5. Только после этого включать `WRITER=llm` по умолчанию

## Второй агент: проверяющий

Когда формулировки пишет модель, появляется работа для второго контура — того самого
«проверяющего агента»:

- **Юридический контур:** проверка, что в посте нет обещаний доходности, нет умолчания об
  условиях (ст. 28 ФЗ «О рекламе»), маркировка рекламы на месте
- **Фактический контур:** каждое число в тексте подтверждено фактом; если факт старше
  `FACT_TTL_DAYS` — перепроверить источник до публикации
- **Редакторский контур:** соответствует ли текст теме журнала, нет ли канцелярита, не дублирует
  ли прошлый пост

Технически это не «второй ИИ», а второй набор проверок: сначала механические (уже есть),
потом контур с моделью, который читает пост и объясняет, что не так. Решение всё равно за человеком:
панель показывает вердикт обоих контуров, публикует владелец.
