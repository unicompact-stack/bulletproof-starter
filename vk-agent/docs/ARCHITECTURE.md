# Устройство проекта

Коротко: **тематика** и **площадка** — это настройки, а не код. Логика одна и та же для банков,
вакансий и того, что появится дальше. Всё, что попадает в пост, проходит через факты и проверки.

## Два уровня настроек

```
profiles/<тематика>/          ЧТО мы пишем              channels/channels.json   КУДА пишем
  profile.json                  название, объект, экстрактор   канал, адаптер, лимит
  subjects.json                 объекты (банк, работодатель)  enabled: включается ли
  rubrics.json                  типы постов + нужные факты
  hooks.json / bodies.json      формулировки
  disclaimers.json              обязательные оговорки
  stopwords.json                запрещённые слова
  templates/*.md                каркас поста
  journal/*.md                  темы, ротируются по очереди
  knowledge/*.md                заметки по объектам (для человека)
```

## Где что лежит во время работы

Всё изменяемое — отдельно от настроек, чтобы в git попадало только описание тематики:

```
data/<тематика>/facts/<объект>.json   база фактов: значение + дата + источник
data/<тематика>/history.jsonl         журнал сборок и публикаций
data/<тематика>/cache/                последние загруженные страницы
queue/<тематика>/<пост>.json          черновики постов
```

Три тематики — три независимые папки. Факты банков физически не могут попасть в пост про
вакансию, а история одной тематики не влияет на подбор темы в другой.

## Поток данных

```
1. profiles/<т>/subjects.json   — что и с каких страниц парсить
2. src/fetch.js                 — загрузка страниц (или фикстуры в офлайне)
3. src/extractors/<т>.js        — разбор: цифры, суммы, сроки, новости
4. data/<т>/facts/              — база фактов
5. src/generate.js              — сборка текста: хук, лид, факты, абзацы, призыв, оговорка, хештеги
6. src/checks.js                — 15 проверок; ошибки блокируют публикацию
7. queue/<т>/                   — черновик поста
8. panel/page.html              — человек смотрит, правит, жмёт «Опубликовать»
9. src/publish.js               — отправка на все включённые площадки
        └── src/channels/<площадка>.js — адаптер: ВК работает, остальные — заглушки
```

## Модули

| Файл | Ответственность | Чего не делает |
|---|---|---|
| `src/profile.js` | Загрузка и проверка тематики, все пути от неё | Ничего не знает про посты |
| `src/util.js` | Файлы, даты, `.env`, аргументы | Ничего не знает про тематики |
| `src/config.js` | Настройки активной тематики | Без логики |
| `src/subject.js` | Объекты тематики, база фактов | Не ходит в сеть |
| `src/parse.js` | Общие примитивы разбора: проценты, суммы, даты, таблицы | Тематики не знает |
| `src/extractors/*.js` | Разбор страниц конкретной тематики | Не сохраняет |
| `src/extractors/index.js` | Реестр экстракторов | — |
| `src/fetch.js` | Загрузка, кэш, слияние фактов | Не собирает текст |
| `src/render.js` | Мини-шаблонизатор | Без бизнес-логики |
| `src/generate.js` | Выбор рубрики, темы, хука, абзацев; сборка поста | Не публикует |
| `src/checks.js` | Правила проверки поста | Не правит текст |
| `src/history.js` | Журнал, подбор неиспользованной темы, сводка по площадкам | — |
| `src/channels/index.js` | Реестр площадок, лимиты, маршрутизация публикации | Не знает про тексты |
| `src/channels/<п>.js` | Адаптер площадки: запросы к API площадки | Не решает, что публиковать |
| `src/publish.js` | Публикация на несколько площадок, запись в историю | Не обходит ошибки проверок |
| `src/preview.js` | HTTP-сервер панели и JSON-API | Не содержит текстов |
| `src/cli.js` | Команды терминала | Тонкий слой |

Правило разделения: модуль, который **решает** (проверки, генерация), не занимается побочными
эффектами (сеть, файлы). Поэтому логику проверяют тестами без подмены сети.

## Как добавить новую тематику

1. `cp -r profiles/vacancies profiles/<новая>` — за основу берётся ближайшая по смыслу
2. `profile.json` — id, название, `subject_label` («Магазин», «Товар»), имя экстрактора
3. `subjects.json` — объекты: id, название, псевдонимы, ссылки, хештеги, тон, источники
4. `rubrics.json` — типы постов и **обязательные факты** для каждого
5. `hooks.json`, `bodies.json` — формулировки; `journal/` — темы
6. `src/extractors/<имя>.js` с функцией `factsFromHtml(html, source)` и регистрация
   в `src/extractors/index.js`
7. Фикстуры в `test/fixtures/<новая>/` + тест в `test/profile.test.js`

Код конвейера не меняется. Это проверяется тестом «у каждой тематики свои объекты, рубрики и темы».

## Как добавить новую площадку

1. `src/channels/<имя>.js` с `readiness()`, `check()`, `publish({ text, schedule, ... })`
2. запись в `src/channels/index.js` в `ADAPTERS`
3. запись в `channels/channels.json`: адаптер, лимит, `enabled: false`

Пока адаптер не написан, площадка честно отвечает «не готова»: в сухом прогоне помечается
как «ушло бы», в боевом — падает с ошибкой. Молча пропускать площадку нельзя: пост
«опубликован», а его никто не видел.

## Тесты

`npm test` — 76 тестов, каждый файл работает в своей временной копии (`test/helpers.js`),
поэтому настоящие факты, очередь и история не портятся.

| Файл | Что проверяет |
|---|---|
| `test/parse.test.js` | Разбор фикстур: проценты, суммы, даты, таблицы, новости, тип страницы |
| `test/collect.test.js` | Офлайн-сбор: попадание фактов в базу, отсутствие дублей, отчёты |
| `test/generate.test.js` | Сборка поста: структура, дата у цифры, детерминизм, `needs-data` |
| `test/checks.test.js` | По одному случаю на каждое правило проверок |
| `test/publish.test.js` | Блокировка плохих постов, сухой прогон, остановка батча |
| `test/profile.test.js` | Универсальность: переключение тематики, изоляция данных, вторая тематика |
| `test/channels.test.js` | Площадки: реестр, лимиты, заглушки, многоточечная публикация |

Правило: новое правило в `checks.js` без теста — не готовая работа. То же для новой тематики
и новой площадки.
