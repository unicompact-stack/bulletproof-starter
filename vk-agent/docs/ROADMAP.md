# План развития

Правило: следующий этап начинается только когда закрыт предыдущий. Незакрытый пункт — это не
«почти готово», это неготово.

## Этап 0. Технический каркас — сделан

Факты со страниц, сборка постов по шаблонам, 15 проверок, панель превью, публикация
с сухим прогоном, 76 тестов. Проверено на фикстурах, без интернета.

**Чего не хватает для закрытия:** живого прогона на настоящих сайтах и настоящей публикации.
Это делается на машине с интернетом и ключом ВК.

- [ ] `npm run fetch -- --subject alfa` без `--offline` — все источники разобрались
- [ ] Первые факты сверены со страницей вручную
- [ ] Пост опубликован в тестовое сообщество через `--live`
- [ ] Ключ с нужными правами (Записи на стене + Управление сообществом)

## Этап 1. Универсальность — сделан

Тематика вынесена в настройки, площадки — в реестр с адаптерами. Вторая тематика
(вакансии) работает наравне с первой.

**Чего не хватает для закрытия:** подтверждения на живых данных, что профиль подхватывает
реальные страницы так же, как фикстуры.

- [ ] `PROFILE=vacancies npm run fetch -- --subject bystro` на настоящем сайте
- [ ] Новая рубрика добавлена без правки `src/` — подтвердить на практике

## Этап 2. Наполнить данными

- [ ] Актуальные страницы-источники по всем нужным банкам
- [ ] Заполнить `profiles/banks/knowledge/*.md` — тон и запреты по каждому банку
- [ ] Страницы акций: рубрика `akciya` пока всегда `needs-data`, пока нет источника с дедлайном
- [ ] Кредитные карты (факты `grace_period`, `limit_max`)
- [ ] Расширить журналы: с 5 тем до 8-10 в каждой тематике

**Критерий:** по каждой нужной рубрике пост собирается со статусом `ready` без ручных правок.

## Этап 3. Живые формулировки (нейросеть)

Пошагово — в [AI-STEP.md](AI-STEP.md).

- [ ] Факт-чекер: любое число в тексте подтверждено фактом из базы
- [ ] Вынести шаблонный сборщик в `src/write.js` (поведение не меняется)
- [ ] Реализация через Claude Code headless или API-ключ, флаг `WRITER=template|llm`
- [ ] Прогон 10-20 постов, ручной отбор удачных формулировок обратно в `hooks.json`

**Критерий:** текст перестал быть заметно шаблонным, факт-чекер ни разу не пропустил
выдуманное число.

## Этап 4. Проверяющий агент

Не «второй ИИ, который всё перечитывает», а второй контур поверх первого. Механические
проверки уже есть; добавляются те, что требуют суждения.

- [ ] Юридический контур: обещания доходности, умолчание об условиях (ст. 28 ФЗ «О рекламе»),
  маркировка на месте
- [ ] Фактический контур: каждое число подтверждено фактом; факт старше `FACT_TTL_DAYS` —
  перепроверить источник до публикации
- [ ] Редакторский контур: тема журнала, канцелярит, повтор прошлого поста
- [ ] Вердикт обоих контуров виден в панели рядом с механическими проверками

**Критерий:** проверяющий находит 9 из 10 подложенных ошибок (набор с известными проблемами)
и не блокирует нормальные посты.

## Этап 5. Вторая площадка

- [ ] Написать адаптер Telegram: `sendMessage` в Bot API, ключ и id канала в `.env`
- [ ] Включить площадку в `channels/channels.json`, снять заглушку
- [ ] Проверить, что лимит длины и разметка работают на второй площадке
- [ ] То же для Дзен — с учётом требований к карточке и обложке

**Критерий:** одна команда публикует пост на две площадки, обе отмечены в истории.

## Этап 6. Визуал

- [ ] Картинки к постам: шаблонная обложка с цифрой из фактов (без выдуманных данных)
- [ ] Логотипы объектов (с учётом прав на использование товарных знаков)
- [ ] Проверка «цифра на картинке = цифра в факте»

**Критерий:** в посте есть картинка, и цифра на ней совпадает с текстом.

## Этап 7. Расписание

- [ ] Календарь в панели: сколько постов и про что на неделю
- [ ] Отложенные записи по всем включённым площадкам
- [ ] Напоминание владельцу: «пост на завтра не собран»
- [ ] Ограничение частоты: не больше N постов в неделю на объект

**Критерий:** неделя постов планируется одним действием, публикация идёт без участия человека,
но каждую запись видно заранее.

## Этап 8. Агент уровнем выше

Только после того, как наберётся история за месяц. Подробно — в
[AGENT-ABOVE.md](AGENT-ABOVE.md).

- [ ] Разметка истории: площадка, оффер, партнёрская ссылка, ожидаемая выплата
- [ ] Учёт: сколько заработали, где убыток
- [ ] Решение «масштабировать, менять оффер или закрывать»
- [ ] Согласование работы контент-агента с целью недели
- [ ] Стоп-правила: запрет публикации, если условия не выполнены

**Критерий:** контент-агент не принимает решений о деньгах, верхний агент — о текстах.
Граница не размывается.

## Этап 9. Обратная связь

- [ ] Сбор статистики постов (просмотры, реакции, комментарии) через API ВК
- [ ] Отчёт: какие хуки и темы работают лучше
- [ ] Подстановка успешных формулировок вперёд очереди

**Критерий:** раз в месяц видно, что зашло, и это меняет выбор хуков.
