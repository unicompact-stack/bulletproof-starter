# План развития

Правило: следующий этап начинается только когда закрыт предыдущий. Незакрытый пункт — это не
«почти готово», это неготово.

## Этап 0. Каркас — сделан

Факты со страниц банков, сборка постов по шаблонам, 14 проверок, панель превью, публикация
с сухим прогоном, 48 тестов. Проверено на фикстурах, без интернета.

**Чего не хватает для закрытия:** живого прогона на настоящих страницах банков и настоящей
публикации. Это делается на машине с интернетом и ключом ВК.

- [ ] `npm run fetch -- --bank alfa` без `--offline` — все источники разобрались
- [ ] Первые факты руками сверены со страницей банка (глазами)
- [ ] Пост опубликован в тестовое сообщество через `--live`
- [ ] Ключ с нужными правами (Записи на стене + Управление сообществом)

## Этап 1. Наполнить данными

- [ ] Добавить актуальные страницы-источники по всем нужным банкам
- [ ] Заполнить `knowledge/banks/*.md` — тон и запреты по каждому банку
- [ ] Добавить страницы акций: рубрика `akciya` сейчас всегда `needs-data`, пока нет источника с дедлайном
- [ ] Добавить кредитные карты (факты `grace_period`, `limit_max`)
- [ ] Расширить журнал: 8-10 тем вместо 5

**Критерий:** по каждой нужной рубрике пост собирается со статусом `ready` без ручных правок.

## Этап 2. Живые формулировки (нейросеть)

Пошагово — в `docs/AI-STEP.md`.

- [ ] Факт-чекер: любое число в тексте подтверждено фактом из базы
- [ ] Вынести шаблонный сборщик в `src/write.js` (поведение не меняется)
- [ ] Реализация через Claude Code headless или API-ключ, флаг `WRITER=template|llm`
- [ ] Прогон 10-20 постов, ручной отбор удачных формулировок обратно в `config/hooks.json`

**Критерий:** текст перестал быть заметно шаблонным, факт-чекер ни разу не пропустил
выдуманное число.

## Этап 3. Проверяющий агент

- [ ] Контур проверки по ст. 28 ФЗ «О рекламе»: нет обещаний доходности, нет умолчания об условиях
- [ ] Перепроверка источника, если факт старше 30 дней
- [ ] Редакторский контур: тема журнала, канцелярит, повтор прошлого поста
- [ ] Вердикт проверяющего виден в панели рядом с механическими проверками

**Критерий:** проверяющий находит 9 из 10 подложенных ошибок (тестовый набор с известными
проблемами) и не блокирует нормальные посты.

## Этап 4. Визуал

- [ ] Картинки к постам: шаблонная обложка с цифрой из фактов (без выдуманных данных)
- [ ] Логотипы банков (с учётом прав на использование товарных знаков)
- [ ] Проверка «цифра на картинке = цифра в факте»

**Критерий:** в посте есть картинка, и цифра на ней совпадает с текстом.

## Этап 5. Расписание

- [ ] Календарь в панели: сколько постов и про что на неделю
- [ ] Отложенные записи ВК по расписанию
- [ ] Напоминание владельцу: «пост на завтра не собран»
- [ ] Ограничение частоты: не больше N постов в неделю на банк

**Критерий:** неделя постов планируется одним действием, публикация идёт без участия человека,
но каждую запись видно заранее.

## Этап 6. Обратная связь

- [ ] Сбор статистики постов (просмотры, реакции, комментарии) через API ВК
- [ ] Отчёт: какие хуки и темы работают лучше
- [ ] Подстановка успешных формулировок вперёд очереди

**Критерий:** раз в месяц видно, что зашло, и это меняет выбор хуков.

## Этап 7. Вторая площадка

- [ ] Вынести площадку за интерфейс: ВК сейчас, Telegram и Дзен позже
- [ ] Учитывать формат каждой площадки (длина, ссылки, разметка)

**Критерий:** одна и та же тема публикуется на двух площадках без ручной переделки.
