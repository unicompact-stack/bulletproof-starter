# База фактов

Факты — единственный источник цифр для постов. Агент не придумывает числа: если факта нет,
пост помечается `needs-data` и не публикуется.

## Откуда берутся

- `npm run fetch -- --bank alfa` — загружает страницы банка из `config/banks.json` и раскладывает
  найденное по файлам `knowledge/facts/<bank>.json`
- `npm run fetch -- --bank alfa --offline` — то же, но на тестовых фикстурах из `test/fixtures/`,
  без интернета (так можно посмотреть, как работает разбор, не выходя в сеть)

Файлы фактов в git не хранятся: это локальные данные конкретной машины, вроде `.business/`
в шаблоне. Формат — в `_example.json`.

## Формат

```json
{
  "bank_id": "alfa",
  "updated": "2026-10-04",
  "facts": {
    "cashback_rate": {
      "label": "Кэшбэк",
      "value": "до 10% в выбранных категориях",
      "date": "2026-09-15",
      "source": "https://alfabank.ru/everyday/debit-cards/",
      "product": "Альфа-Карта"
    }
  }
}
```

- `value` — как это написано в посте, рядом с меткой. Не округляй и не «причёсывай»: текст должен
  совпадать с сайтом банка
- `date` — дата, на которую факт верен (берётся с самой страницы банка, если её там видно)
- `source` — откуда факт. Хранится, чтобы можно было перепроверить руками

## Какой факт для какой рубрики обязателен

Список — в `config/rubrics.json`, поле `required_facts`. Если обязательного факта нет, проверка
блокирует публикацию и пишет, чего не хватает.

## Свежесть

Факт старше `FACT_TTL_DAYS` (по умолчанию 30 дней) даёт предупреждение при сборке поста.
Ставки по вкладам меняются чаще, кэшбэк реже — срок можно менять в `.env`.

## Ручное заполнение

Можно заполнить файл руками — например, если условия получены от менеджера банка. Правило одно:
у каждого факта должна быть дата и источник. Без даты проверка заблокирует пост.
