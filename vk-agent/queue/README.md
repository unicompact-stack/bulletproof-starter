# Очередь постов

Здесь лежат черновики: `queue/<тематика>/<дата>-<объект>-<рубрика>.json` — результат
`npm run generate`.

В git очередь не хранится: это рабочий стол, а не архив. История публикаций — в соцсети,
и дублировать её в репозитории незачем.

## Что внутри файла

- `text` — готовый текст поста (его видно в панели, его же отправляет публикация)
- `facts` — список фактов с датами и источниками; у каждого знания есть `line` в том виде,
  в каком он попал в текст
- `checks` — результат проверок: `errors` (блокируют публикацию) и `warnings` (не блокируют)
- `profile` — тематика, к которой относится пост
- `subject_id` / `subject_name` — объект (банк, работодатель)
- `status`:
  - `ready` — готов к публикации
  - `needs-data` — не хватает обязательных фактов, надо запустить `npm run fetch`
  - `blocked` — проверки нашли ошибку (запрещённая формулировка, цифра без даты и т. п.)
  - `published` — уже отправлен, повторно не уйдёт

## Как посмотреть, что в очереди

```bash
npm run checks                      # сводка по активной тематике
npm run checks -- --id <id>         # разбор проверок одного поста
npm run status                      # сколько постов накопилось
```

## Как опубликовать

```bash
npm run publish -- --id <id>                        # сухой прогон: наружу ничего не уходит
npm run publish -- --id <id> --live                 # реальная публикация
npm run publish -- --id <id> --channels vk,telegram  # только на указанные площадки
npm run publish -- --id <id> --schedule 2026-10-06T10:00
```

Без `--live` команда покажет, что и куда ушло бы. Это безопасный способ проверить площадки и
график до настоящей публикации.
