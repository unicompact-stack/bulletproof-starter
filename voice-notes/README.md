# Заметки — голосовые заметки (PWA)

Одностраничное приложение на чистом HTML/CSS/JS: говоришь в микрофон — текст
появляется вживую, после 4 секунд тишины заметка сохраняется сама. Работает
полностью офлайн после первой загрузки (включая распознавание речи).

Без фреймворков, без сборки, без CDN. Тёмная тема, мобильная вёрстка (390×844 и
больше), safe-area для iPhone и Android.

---

## ⚠️ Как запускать (и почему не двойным кликом)

Приложение **обязано** открываться через локальный сервер или по HTTPS:

```bash
cd voice-notes
python3 -m http.server 8000
# затем открой http://localhost:8000
```

Почему так:

- **`file://`** — Chrome считает такой контекст небезопасным: `navigator.mediaDevices`
  недоступен, `getUserMedia` и Service Worker заблокированы. Заметки при этом
  напечатать можно, а записать голос — нет.
- **`http://` на внешнем адресе** (`http://192.168.1.5:8000`) — то же самое:
  небезопасный контекст.
- **`http://localhost`** и **`https://`** — безопасный контекст: микрофон,
  IndexedDB, Cache API и Service Worker работают.

Если открыть `index.html` двойным кликом, приложение не «молча упадёт», а покажет
экран с объяснением и командой для запуска сервера. Это единственное, что можно
сделать в такой ситуации.

### Проверка на телефоне

- **Android по USB:** `adb reverse tcp:8000 tcp:8000`, затем на телефоне открой
  `http://localhost:8000` — это безопасный контекст, работает и микрофон, и SW.
- **iPhone / по сети:** нужен настоящий HTTPS (валидный сертификат) — например,
  туннель (`cloudflared`, `ngrok`) или локальный прокси с сертификатом.
  Самоподписанный сертификат Safari не примет как безопасный контекст.

## Как работает распознавание

Движок выбирается автоматически при старте каждой записи, настроек у
пользователя нет:

| Условие                                   | Движок            | Что нужно          |
|-------------------------------------------|-------------------|--------------------|
| `navigator.onLine` и есть `SpeechRecognition` | Web Speech API | интернет           |
| иначе                                     | Vosk WASM        | скачанная модель   |

Если во время онлайн-записи Web Speech падает с ошибкой `network`, приложение
само переключается на Vosk, не теряя уже наговоренный текст.

### Web Speech API

- `lang = 'ru-RU'`, `continuous = true`, `interimResults = true`;
- текст берётся из `event.results[i][0].transcript` (не `text`);
- **Android Chrome** всё равно обрывает сессию после каждой фразы — поэтому в
  `onend` распознавание перезапускается, но не больше 3 раз подряд без нового
  текста;
- `recognition.stop()` вызывается только если `isListening === true` (на Android
  вызов на неактивном экземпляре синхронно дёргает `onend` и ломает перезапуск).

Web Speech в Chrome **требует интернет** и отправляет аудио на серверы Google.
Офлайн он не работает — для этого и нужен второй движок.

### Vosk (офлайн)

- `getUserMedia({audio: {echoCancellation, noiseSuppression, channelCount: 1, sampleRate: 16000}})`;
- `new AudioContext({sampleRate: 16000})`, при необходимости — линейный ресемплер
  до 16 кГц (если браузер проигнорировал частоту);
- `createScriptProcessor(4096, 1, 1)` + `GainNode(0)` → `destination`
  (ScriptProcessor должен быть подключён, но микрофон не должен уходить в динамики);
- в `onaudioprocess`: `recognizer.acceptWaveformFloat(chunk, 16000)`;
- `partialresult` → живой текст, `result` → финальные фрагменты;
- на остановке: `retrieveFinalResult()` → пауза 400 мс (досчитать фразу) →
  `recognizer.remove()`, закрытие `AudioContext`, `track.stop()`.

Модель всегда передаётся в `Vosk.createModel()` как **blob: URL** — воркер
создаётся из blob и не видит кэш Service Worker, относительный путь ему тоже не
доступен. После загрузки blob освобождается через `URL.revokeObjectURL`.

## Модель: что именно лежит и почему

В `models/` лежит **`vosk-model-small-ru-0.4.tar.gz`** (40 810 065 байт) —
официальная русская модель Vosk из официального демо-репозитория
`ccoreilly/vosk-browser` (ветка `gh-pages`).

Почему не `vosk-model-small-ru-0.22`, как в ТЗ: сайт `alphacephei.com` недоступен
из окружения, где собирался проект, поэтому скачать именно 0.22 не удалось.
0.4 — та же линейка small-моделей для русского, тот же размер (≈40 МБ), новее и
точнее. Архив содержит папку `vosk-model-small-ru-0.4/` со всеми подпапками
(`am/`, `conf/`, `graph/`, `ivector/`) — как и требуется.

### Если нужен именно 0.22

1. Скачай `vosk-model-small-ru-0.22.zip` с <https://alphacephei.com/vosk/models>.
2. Распакуй и упакуй в tar.gz **папкой**, а не файлами россыпью:

   ```bash
   unzip vosk-model-small-ru-0.22.zip
   tar -czf vosk-model-small-ru-0.22.tar.gz vosk-model-small-ru-0.22/
   ```

3. Положи архив в `models/`.
4. Поменяй одну строку в `vosk-engine.js`:

   ```js
   var MODEL_PATH = 'models/vosk-model-small-ru-0.22.tar.gz';
   ```

   и подними версию SW (`VERSION` в `sw.js`), чтобы старый кэш модели не мешал.
   Папку `voice-notes-models-v1` можно оставить — файл другой, старый просто
   перестанет использоваться (удалить можно через DevTools → Application →
   Cache Storage).

Модель распространяется по лицензии Apache 2.0, текст — в
`models/vosk-model-COPYING.txt`.

### Как получить `lib/vosk/vosk-browser/dist/vosk.js`

```bash
npm i vosk-browser@0.0.8
mkdir -p lib/vosk/vosk-browser/dist
cp node_modules/vosk-browser/dist/vosk.js lib/vosk/vosk-browser/dist/vosk.js
```

Контрольные суммы уже положенных файлов:

```
29504515526e974f4cb053cf08811c4de5fb2a74007c0a5a957db50eaa8d5d0c  lib/vosk/vosk-browser/dist/vosk.js
b855cf79a513023af4090739caa407203754d7db98ccb3b8d4162f5d7f6a3f8e  models/vosk-model-small-ru-0.4.tar.gz
```

### Отличия от ТЗ: где `vosk-processor.js`

В опубликованном пакете **`vosk-browser@0.0.8` файла `vosk-processor.js` нет** —
в `dist/` лежат только `vosk.js`, `model.d.ts`, `interfaces.d.ts` и `utils/`.
Проверяется одной командой: `ls node_modules/vosk-browser/dist/`.

Более того, в этой сборке **AudioWorklet не используется вообще** (в `vosk.js`
нет ни `audioWorklet`, ни `registerProcessor`), а официальный пример
`ccoreilly/vosk-browser` строит аудио на `ScriptProcessorNode`. Поэтому копировать
нечего: движок запускается без отдельного файла-процессора. Пайплайн —
ровно тот, что описан в ТЗ (`ScriptProcessor`, 16 кГц, `acceptWaveformFloat`),
поэтому старые Android тоже поддерживаются.

## Первый запуск и офлайн

1. При старте приложение вызывает `navigator.storage.persist()`, чтобы браузер не
   вытеснил 40 МБ модели при нехватке места (если браузер откажет — работаем дальше).
2. Если модели нет в кэше, она скачивается в фоне с прогрессом
   «Качаем голосовой движок… X%»: `fetch` + чтение потока, проценты от
   `Content-Length`, потолок 99 % до конца потока, до 3 попыток.
3. Перед сохранением проверяется ответ: тип не `text/html`, размер ≥ 10 МБ, а
   перед `Vosk.createModel` — gzip-магия `1f 8b`. Не прошло — кэш удаляется и
   модель качается заново (self-heal).
4. Тяжёлая инициализация (`Vosk.createModel`, WASM + разбор архива) — лениво, при
   первой записи. На телефоне это 5–30 секунд, статус честно показывается на
   экране записи.

`python3 -m http.server` отдаёт `.tar.gz` как `application/gzip` или
`application/x-tar` — проверка типов это учитывает.

### Кэши Service Worker

- `voice-notes-static-v1.0.0` — сайт: html/css/js/иконки/vosk.js (cache-first,
  для навигации — network-first с офлайн-фолбэком);
- `voice-notes-models-v1` — модель, скачивается страницей через Cache API.
  **Не удаляется** при активации нового SW: при обновлении стираются все кэши,
  кроме текущего статического и кэша модели.

После правок в `app.js` / `style.css` / `sw.js` поднимай `VERSION` в `sw.js` —
иначе пользователи останутся на старом кэше.

## Что проверено (и как повторить)

Проверялось в headless Chromium 153 на `http://127.0.0.1:8000`
(скрипты прогонялись вне репозитория, модель качается с локального сервера):

- приложение открывается, пустое состояние и бейдж «онлайн»;
- модель скачивается с прогрессом, попадает в `voice-notes-models-v1`
  (`Content-Type: application/gzip`, 40 810 065 байт), `vosk.js` — в статический кэш;
- создание, поиск, правка, удаление заметок; данные переживают перезагрузку;
- DevTools-offline + перезагрузка: приложение поднимается из Service Worker,
  заметки на месте;
- офлайн-запись: движок `Vosk офлайн`, модель разворачивается из кэша, статус
  «Слушаю…», аудио-пайплайн активен, авто-стоп по тишине срабатывает, сессия
  корректно закрывается (`VoskEngine.isActive() === false`), тоста об ошибке нет;
- битый кэш модели (подменён на HTML) — при перезагрузке перекачивается сам;
- активация нового SW удаляет чужие кэши, но не трогает модель;
- `file://` — показывается экран «Открой через localhost или HTTPS», ошибок JS нет;
- `node --check` для `app.js` / `vosk-engine.js`, юнит-проверки чистки текста
  (слова-паразиты, повторы, заглавная буква, точка).

**Что нельзя проверить в песочнице:** реальное распознавание русской речи —
здесь нет микрофона. Vosk-движок запускается и принимает аудио, но качество
текста нужно проверить на живом устройстве (пункт 5 из приёмки: Android по HTTPS,
авиарежим, запись с иконки).

## Ограничения, о которых честно

- **Web Speech** в Chrome требует интернет и отправляет аудио в Google. Офлайн —
  только Vosk.
- **iOS Safari** не поддерживает `SpeechRecognition` → там всегда Vosk.
  `AudioContext({sampleRate: 16000})` может быть проигнорирован — включается
  встроенный ресемплер.
- Small-модель Vosk понимает обычную речь, но путает имена, термины и числа.
  Для диктовки с шумом лучше писать в тихой комнате.
- Модель занимает ~40 МБ в браузере; при нехватке места браузер может её
  вытеснить (поэтому и вызывается `storage.persist()`), тогда она скачается заново.
- Web Speech в Safari/Chrome на десктопе может требовать разрешения на
  распознавание — ошибка показывается тостом, текст можно дописать вручную.
